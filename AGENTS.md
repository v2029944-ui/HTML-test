# Инструкции ИИ-агентам — HTML-test

Этот репозиторий содержит автономный `index.html` и настольное приложение `tauri/`. При доработках Tauri не удаляйте браузерную версию, защищайте данные от случайной потери, сохраняйте резервное копирование, работу с Excel и проверки целостности данных. Не сливайте незаконченные Draft PR и не включайте функциональность в рабочий интерфейс, пока не прошли соответствующие проверки.

## Совместимость версий во время разработки

**Программа ещё находится в стадии разработки. Обратная совместимость между версиями не требуется и не является условием слияния PR или выпуска новой версии.** Разрешено менять структуру SQLite, форматы внутренних данных, интерфейс и API без поддержки прежних экспериментальных выпусков (включая обновление с 0.1.3). Не тратьте время на обязательные миграции, поддержку старых установщиков и тесты обновления между версиями, если владелец отдельно этого не запросил.

Это **не отменяет** обязательных проверок работы текущей версии, целостности данных, транзакционности импорта, резервного копирования и отказа от случайного удаления/перезаписи файлов. Если изменение несовместимо с ранее созданными данными, ясно укажите это в release notes; не обещайте автоматический перенос. Никогда не удаляйте реальные пользовательские данные без отдельного разрешения.

## Обязательное правило выпуска новой версии

**При выпуске каждой новой версии необходимо создать отдельный GitHub Release с Windows-установщиком и указать, что конкретно изменилось в версии.** Одного EXE в Actions, изменения номера в коде или PR недостаточно. Проверьте, что Release и артефакты доступны, обновите ссылки в README. Нельзя утверждать, что выпуск состоялся, если релиз не опубликован.

Соблюдайте **[полный порядок выпуска](docs/RELEASE_POLICY.md)**: новый уникальный номер, реальные release notes, успешные CI/GUI/данные-проверки, согласие владельца перед публикацией, подписание перед переводом канала онлайн-обновлений. При невозможности завершить выпуск явно указывайте блокирующие причины и не переключайте `tauri-updates`.

Не добавляйте секреты, реальные пользовательские файлы Excel/SQLite или тестовую сборку с WebView2 CDP в Releases.

## Дополнительные ограничения Codex

Перед работой читать [docs/CODEX_SAFETY_RULES.md](docs/CODEX_SAFETY_RULES.md). Эти правила применяются и к задачам из [issue #79](https://github.com/v2029944-ui/HTML-test/issues/79).

- Все изменения — в отдельной ветке через PR. **Не изменять напрямую `main`, не выполнять force-push, слияние или закрытие чужих задач без подтверждения владельца.**
- Нельзя самостоятельно публиковать Release, запускать подписанный `publish`, переиспользовать тег, переключать `tauri-updates`, изменять секреты и правила защиты GitHub.
- Для SQLite, импорта Excel, удаления отчётов, бэкапов, восстановления и updater — отдельный PR с оценкой рисков, тестами отказов и сохранности данных.
- Сохранять автономный `index.html`, корректность `null` и ограниченные SQL-запросы. Нельзя заменять отсутствие данных нулём, ослаблять тесты или скрывать известные ошибки.
- Не коммитить реальные пользовательские Excel/SQLite/JSON, секреты, подписанные установщики и диагностические сборки.
- **Не добавлять «Историю импортов» и «Сохранённые наборы фильтров» без нового задания:** эти возможности ранее исключены.

При архитектурном ревью Rust используйте [deslop-please](README.md#разработка-и-проверки) для анализа зависимостей. Сопоставляйте предупреждения с реальными вызовами и проверяйте поведение штатными тестами.

Наличие AGENTS.md само по себе не заменяет GitHub Rulesets: владельцу следует дополнительно защитить ветку `main`.
