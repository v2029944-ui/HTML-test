# Дата начала обычного импорта

Это отдельное расширение исправления из PR #16. Оно не возвращает дату из имени
«Анализ.xlsx» и не назначает найденную дату автоматически. Недельные, месячные и
дневные обычные отчёты показывают найденные даты с именем листа и адресами
подписи/значения. Кнопка «Выбрать» — явное действие пользователя. Уже указанная
дата сохраняется, пока пользователь не изменит её или не выберет другой файл.

Распознаются только явные подписи в заголовке первого набора столбцов:

- «Начало периода», «Начало отчётного периода», «Дата начала первой недели»,
  «Начало месяца», «Начало дня» и соответствующие формы: значение после двоеточия
  либо в следующей ячейке;
- ISO `YYYY-MM-DD`, полная дата `DD.MM.YYYY` / `DD/MM/YYYY`, типизированная дата
  Excel, уже преобразованная существующим читателем;
- для месяца — `YYYY-MM` или первый день месяца;
- «Период с … по …», когда обе даты полные и диапазон точно соответствует
  выбранному одному дню, неделе или календарному месяцу.

Дата печати, дата в имени файла, короткий год, неподписанное число Excel и даты
последующих наборов не считаются доказательством начала первого периода.
Объединённая подпись с датой в другой ячейке не обходится эвристически. Широкие
дневные таблицы продолжают использовать свой отдельный разбор заголовков, включая
систему 1904; этот код его не меняет. Расширение не заявляет распознавание любой
произвольной шапки Excel или отдельную нативную Rust-реализацию этих правил.

Проверка ограничена первыми 64 строками до/включая строку заголовков первого
набора и 64 столбцами внутри его области; максимум 16 источников даты, подпись
не длиннее 4096 символов. Усечение явно отмечается и требует подтверждения.
Интерфейс не выполняет новый полный проход по большой книге при каждом вводе.

Если найдено несколько разных дат или дата пользователя отличается от найденной,
проверка требует подтверждения. Отказ очищает предпросмотр и блокирует сохранение.
При изменении файла/листа/настроек/даты во время асинхронного подтверждения старый
ответ не применяется. После выбора другого файла исчезают и дата, и источники,
и подтверждение. Если надёжная дата не найдена, поле остаётся пустым; сохранение
требует явного ввода. Неизвестная дата не заменяется сегодняшней или прошлой.

В папочном режиме противоречие содержимого и сохранённого правила останавливает
автозагрузку этого файла. Прежние отчёты и правило сохраняются. Ручная проверка
показывает источники и позволяет подтвердить выбранную дату; это не переписывает
правило. Успешная согласованная автозагрузка показывает адрес найденной даты,
а первый отчёт сохраняет небольшое информационное `periodStartEvidence`.
Старое предупреждение о возможной ошибке 19.10.2026 остаётся из PR #16.

Локальные проверки без Actions:

```sh
node tests/test_period_date_evidence.cjs
node tests/test_desktop_annual.cjs
python -m unittest discover -s tests -p test_period_date_evidence.py -v
python -m unittest discover -s tests -p test_import_controls.py -v
```

Проверки Chromium/Linux не являются проверками Windows/WebView2. Полный переход
на нативный импорт и ограниченные SQL-запросы выполняется отдельными PR.
