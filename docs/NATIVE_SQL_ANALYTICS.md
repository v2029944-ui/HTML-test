# D4c — SQL-аналитика без полной загрузки отчётов

Новый SQL-режим Tauri теперь включает первое подключение строгой D2-аналитики: диапазоны дневных, недельных и месячных периодов; полный/неполный ряд, пропуски, сумма, количество, среднее и число проблем качества.

## Подготовка
Пользователь явно запускает «Подготовить индексы». UI перечисляет заголовки D1 по типу отчёта в SQL, команда `native_analysis_index_page` индексирует **не более 20 отчётов за один вызов** через Rust `analysis_index_report` и возвращает курсор. JS хранит только курсор и число обработанных отчётов; не загружает JSON отчётов. Между запросами пользователь может остановить дальнейшие порции. Отмена не прерывает уже запущенный парсер текущей порции; результаты частичной индексации остаются в производных таблицах SQLite, исходные документы неизменны. После полного прохода команда `native_analysis_index_settings` индексирует настройки потоково. Изменение типа требует повторной подготовки; изменение ревизии базы отклоняет устаревшие запросы.

## Расчёт
Для выбранных дат, типа и списка подразделений из настроек команда `native_analysis_range` создаёт **временный фильтр в SQLite** (`analysis_filter_create` + append + seal), выполняет `analysis_range_summary` и затем удаляет этот фильтр независимо от успешности расчёта. Это не функция сохранённых наборов фильтров. При неполном ряде `total.count` / `total.amount` / `total.average` возвращаются `null` и отображаются «—», а не ложным нулём. Показываются ошибки, дубликаты и перекрытия периодов. Ввод недель/месяцев должен соответствовать правилам календаря D2; некорректные даты отвергаются.

## Границы
Это отдельная экспериментальная страница. При обычном запуске пока работает прежний `load_data` и прежняя аналитика, а полная реализация сравнения работ, подразделений и CSV ещё не переведена на D2. Метрики считаются для выбранных подразделений из `orgNames`, а не автоматически для всех исторических названий в отчётах. Неизвестные или неполные данные не считаются нулём. Не проводить миграции на рабочей SQLite или публиковать релиз до итоговой проверки Windows CI, корректности на реальных файлах и резервного копирования.

Нативный IPC ограничивает один запрос не более чем 3660 календарными днями, чтобы исключить случайный многотысячелетний перебор временных периодов в SQLite. Неподдерживаемые большие диапазоны завершаются понятной ошибкой без изменения исходных отчётов.
