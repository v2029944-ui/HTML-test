# Размер Excel: диагностика и первые измерения

**Готовится отдельный повышенный профиль только для нативного Rust-импорта.** Числа и оговорки описаны в [NATIVE_XLSX_LIMITS.md](NATIVE_XLSX_LIMITS.md). Браузерные лимиты не меняются; измерения ниже относятся к прежним версиям и не подтверждают безопасность увеличенных порогов.

## Небольшой этап, 17.11.2026

Встроенный читатель XLSX считает отдельно:

- `readStats.cells` — обработанные ячейки с допустимыми адресами, включая пустые оформленные;
- `filledCells` — ячейки со значением, в том числе `0`, `false` и дробные числа;
- `emptyCells` — пустые значения и строки из пробелов;
- `uncachedFormulaCells` — формулы без числового/текстового результата, доступного читателю. Они не считаются оформленными пустыми ячейками и не вычисляются автоматически.

Счётчики общие для всех листов книги. Это временная диагностика чтения, она не записывается в отчёты, JSON-копии или SQLite. Значения ячеек и финансовые расчёты не изменены.

Сообщение об ограничении больше не называет все ячейки «заполненными». Лимит **1 500 000** сохранён: исключение пустых ячеек из защитного счётчика не уменьшило бы память, которую уже занимает XML DOM. Безопасные ограничения **48 МиБ на XML-компонент**, **192 МиБ на распакованную книгу**, **2048 столбцов** также сохранены.

## Воспроизводимый локальный профиль

Используются существующие Playwright, Chromium и генератор синтетических XLSX. Новых зависимостей приложения нет. Запуск вручную, без GitHub Actions:

```sh
PYTHONDONTWRITEBYTECODE=1 python tests/profile_xlsx.py --works-per-org 125 500 --output /tmp/xlsx-profile.json
```

Для локального контрольного файла можно добавить `--excel /путь/Анализ.xlsx`. Скрипт не изменяет книгу, не сохраняет отчёты и не отправляет данные по сети. Его JSON содержит агрегаты; результат с рабочими данными следует хранить локально.

Один замер в Linux/Chromium в общей вычислительной среде (это **не Windows/WebView2**):

| Файл | Ячеек | Чтение XLSX | Разбор отчётов | Пиковая выборка RSS дочерних процессов |
|---|---:|---:|---:|---:|
| 2024 год, 500 строк работ в день | 372 295 | 3,97 с | 2,89 с | 1187 МиБ |
| 2024 год, 2000 строк работ в день | 1 474 795 | 23,66 с | 11,12 с | 2445 МиБ |
| Контрольный обычный Excel, 3 периода | 14 879 | 0,53 с | 0,07 с | 798 МиБ |

В синтетических книгах 366 дней; по 125/500 строк работ в каждом из четырёх подразделений. Это количество строк по подразделениям, а не уникальных названий общих групп. Проверены ожидаемые количество и сумма, отсутствие предупреждений, 183 000/732 000 детальных записей.

RSS измеряется каждые 100 мс через `/proc` и включает Chromium и драйвер Playwright, а также разделяемые страницы памяти. Это не приватная память, не точный пик и не обещание требований к ОЗУ. Исходный уровень составлял около 719–736 МиБ. JS heap после завершения также записывается, но не учитывает всю память XML DOM и не заменяет RSS. Время разбора в таблице не включает загрузку страницы и последующее распознавание справочника. На общей машине значения меняются от запуска к запуску.

Сравнительный одиночный запуск неизменённого читателя на 500 строках/день дал 4,82 с чтения + 3,25 с разбора; ускорение новой версии на основании этих двух запусков не заявляется.

У файла около действующего предела уже заметны задержка и расход памяти. **Безопасность лимита 3 млн этими измерениями не подтверждена**, предел не повышен. Потоковое чтение Rust, работа вне UI-потока, выборочные запросы и пакетные записи SQLite остаются следующими отдельными задачами.

## Проверки

- Новые браузерные тесты: значения `0`, `false`, дроби; пустое оформление; пустые строки; формулы с сохранённым результатом и без него; общий бюджет нескольких листов.
- В тесте границы используется уменьшенный только в тестовой копии порог той же функции. Это проверка логики, а не нагрузочный тест на 1,5 млн ячеек. Профиль выше работает с неизменённым производственным лимитом.
- На контрольном Excel сравниваются полные распознанные отчёты, строки, предупреждения и справочник до/после изменения. Существующие замечания Excel сохраняются, они не исправляются автоматически.
- Диагностика проверена в Linux/Chromium. Отдельный установщик Tauri 0.1.3 собран без Actions из `f26e5e6`, до этой правки. Для включения диагностики в EXE нужны следующая сборка и проверка Windows/WebView2.

## Экспериментальный нативный путь, 17.11.2026

Отдельное ядро `tauri/import-core` постепенно читает ZIP/XML в частную SQLite,
затем преобразует обычные и широкие дневные таблицы, сохраняя строки и диагностику
на диске. Предел браузера **1 500 000** не меняется; основной интерфейс ещё не
переключён на нативный путь. Нативный предел 3 млн проверяется отдельно, вместе с
прежними ограничениями размера XML, книги, координат, коэффициента распаковки и
новым пределом временного хранилища. Это не повышение константы DOM-парсера.

Контракты, воспроизводимые команды и фактические измерения приведены в
[отчёте нативного импорта](NATIVE_IMPORT_PROGRESS.md) и
[описании широкого преобразования](../tauri/import-core/WIDE_REPORTS.md).
Старые числа Chromium выше включают другие процессы и другой набор данных;
их нельзя напрямую сравнивать с памятью одного Rust-процесса. Применение к
рабочей базе, выборочная загрузка приложения, полный интерфейс и Windows/WebView2
остаются отдельными обязательными проверками. Безопасность всего приложения на
3 млн ячеек пока не заявляется.
