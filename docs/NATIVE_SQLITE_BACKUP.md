# D4g — полная резервная копия SQLite

В экспериментальном SQL-режиме Tauri кнопка «Сохранить резервную копию SQLite» вызывает SQLite Online Backup API (`rusqlite::backup::Backup`) в фоновом Rust-потоке. Копия включает отчёты, настройки, BLOB-документы, диагностические данные и служебные таблицы SQLite, в том числе изменения из WAL. Это не экспорт CSV.

Пользователь явно выбирает новый файл `.sqlite3` через Tauri Save dialog. Снимок сначала создаётся в уникальном временном файле той же папки, проверяется с `PRAGMA quick_check` и чтением ревизии, синхронизируется на диск и публикуется через атомарную жёсткую ссылку. **Существующие файлы не перезаписываются.** При ошибке источник не меняется, временный файл удаляется. Для публикации требуется файловая система с поддержкой hard links, обычно NTFS.

Rust-тесты проверяют согласованность JSON BLOB/TEXT и настроек, ревизию и отказ от перезаписи. Node-тесты проверяют явное подтверждение выбора файла и учёт операции в UI. Windows GUI smoke открывает созданную резервную базу после импорта 366 синтетических отчётов и проверяет `quick_check`, число отчётов, настройки и сохранность файла при повторной попытке.

**Восстановление ещё не реализовано.** Нельзя заменять `reports.sqlite3` при работающем приложении: для безопасного восстановления нужно закрыть SQLite-соединения и корректно обработать WAL/SHM, инвалидировать подготовленные импорты и проверить повторное открытие. До появления этого проверенного сценария резервную копию следует хранить отдельно.
