# План развития HTML-test

Дальнейшая разработка сосредоточена на Windows-приложении с Tauri 2 и SQLite. Поддержка автономной браузерной версии завершена. Корневой `index.html` используется при сборке интерфейса Tauri.

## Следующий этап после выпуска 1.11.1 — достоверность количества и графики (23.11.2026)

**Приоритет P0 — новый тип Excel «только количество» ([#113](https://github.com/v2029944-ui/HTML-test/issues/113)).**
На исходной книге `анализ 2 — копия (2).xlsx` из отдельного репозитория `HTML` даты стоят над дневными столбцами «Количество» без столбцов «Сумма». В строке 1700 отмечены расхождения с контрольными итогами: D −2, E −1, J −1, K −3, L −2, M −6. Существующий преобразователь `Context::process` пропускает работу, если отсутствует одно из двух значений `Количество / Сумма`; широкая дневная структура пока требует пары этих показателей. Требуется отдельный распознаватель count-only, сохранение количества без фиктивной денежной суммы, контроль итогов по строкам и адресная диагностика. Отдельно сверить сами исходные итоговые ячейки с детализацией и воспроизвести пользовательские результаты.

**Приоритет P1 — графики и общие фильтры ([#114](https://github.com/v2029944-ui/HTML-test/issues/114)).**
Проверить и исправить реальное скрытие подтверждённых нулевых периодов (с учётом выбранной метрики, без скрытия пропущенных отчётов); при одном периоде не предлагать линейную динамику, оставлять рейтинг/столбцы и возвращать линию для диапазона; пояснить область действия общего фильтра «Показатель». Проверить цвета подразделений, сплошные/штриховые/точечные узоры столбцов, легенду, контраст и масштаб 80/90/100% в обеих темах. Добавить UI, SQL и WebView2 регрессионные тесты.

**Условия завершения:** все шесть контрольных случаев проверены на исходных и нормализованных данных; импорт не теряет строки без суммы; отчёты с недоступной суммой явно отличимы от нулевых; фильтры синхронны с таблицами и CSV; оформление подтверждено в установленном приложении.

## Этап 1 — импорт Excel и удобный календарь отчётов (P0)

### 1.1. Импорт квартальных и годовых книг без дат в шапке

**Задача:** разрешить последовательные пары «Количество / Сумма» без подписанной даты над каждой парой.

**Поведение:** если даты нельзя распознать, пользователь явно выбирает год и квартал или год целиком. Даты назначаются в календарном порядке по выбранному периоду; учитываются длительность кварталов, високосные годы и отдельно расположенные итоговые пары.

**Критерии готовности:**
- Поддерживаются полные даты в шапке и режим назначения последовательных дат; существующий импорт не ухудшен.
- Программа отделяет итоговые пары от дневных, проверяет ожидаемое число дней и не превращает пустые даты/отсутствующие пары в нули.
- При неполном или неоднозначном наборе колонок не предполагает молча, каким датам они соответствуют: требует уточнения/явного подтверждения или прекращает импорт.
- Запрещены дубли дат внутри файла и между выбираемыми листами; итоговые суммы сверяются, ошибки указывают на источник.
- Тесты: все четыре квартала, 365/366 дней, неполная книга, конфликт дат и ошибочная пара итогов.

### 1.2. Распознавание дат в остальных типах отчётов

**Задача:** проверить фактически существующее распознавание дат для дневных, недельных и месячных Excel и закрыть недостающие случаи.

**Поведение:** сначала искать явные даты в заголовках и структуре листа, затем использовать однозначные сведения из имён листов/файла. Для недель и месяцев корректно определять границы периода; полагаться на дату создания файла нельзя.

**Критерии готовности:**
- В предпросмотре видно, откуда взята дата: из ячейки, заголовка/имени либо задана вручную.
- При конфликте дат разных признаков предлагается проверить период; ошибочные даты не сохраняются автоматически.
- Поддержаны переходы через месяц/год, високосный год, пропуски периодов и явный выбор даты.
- Сохранённые правила не теряются при повторной загрузке в текущей версии; совместимость между старыми экспериментальными выпусками не требуется по [политике выпуска](RELEASE_POLICY.md).

### 1.3. Автоматическое определение структуры Excel вместо основного поля «Формат Excel»

**Задача:** упростить базовый сценарий до «Выбрать Excel → Распознать → Проверить → Сохранить».

**Поведение:** определить по содержимому, используется ли структура повторяющихся троек «Работа / Количество / Сумма» либо общий столбец работ с дневными парами. Убрать переключатель «Формат Excel» из основных полей, **оставив ручной выбор в дополнительных настройках**.

**Критерии готовности:**
- Понятно показаны определённая структура, тип периода, дата/диапазон и выбранные листы.
- При неоднозначности программа предлагает оба варианта, не выбирая опасный по догадке.
- Явный ручной выбор имеет приоритет и сохраняется в правилах импорта.
- Старые сохранённые правила работают; автоматический импорт не перезаписывает данные при неожиданной смене структуры.
- Регрессионные тесты для обычных и широких Excel, ручного переопределения и повторной загрузки.

### 1.4. Календарь отчётов: выбор месяцев, недель и дней, закрытие детализации

**Задача:** в разделе «Отчёты» → «Отчёты по периодам» разрешить просмотр и выбор периодов не только по месяцам, но также по неделям и дням, сохраняя понятную сетку **обычного месячного календаря**. Исправить невозможность закрыть раскрытый месяц.

**Поведение:**
- Сохранить годовой обзор с 12 месяцами. Добавить понятное переключение режима отображения/выбора: «Месяцы», «Недели», «Дни». Не путать это переключение с уже имеющимся фильтром **типа источника** (дневной, недельный, месячный), который определяет, какие загруженные отчёты показывать.
- При переходе к неделям или дням отображать дни по привычной сетке месяца (7 столбцов, понедельник — воскресенье), а не сплошным перечнем дат. В режиме недель выбирать неделю целиком; в режиме дней — конкретный день. Показывать подробности выбранного периода и связанные исходные отчёты.
- В режиме месяцев сохранять выбор месяца и его детализацию. Повторное нажатие на выбранный месяц **сворачивает** его; кнопка «К списку месяцев» действительно закрывает детализацию, сбрасывает выделение и возвращает фокус к нужному месяцу, а не только прокручивает страницу. Предусмотреть явную кнопку закрытия и работу Escape.
- Выбранный год, месяц, режим, тип источника и открытый период должны быть понятно обозначены. Переключение режимов или года не оставляет устаревшую панель деталей и некорректный `aria-expanded`.
- Недели, пересекающие границу месяца или года, отображать последовательно и без двойного учёта. Недельные и месячные **итоги источников не распределять по дням**: показывать их отдельно от реальных дневных показателей.
- Сохранять различие «отчёт отсутствует / явный ноль / неполные данные / ошибка / конфликт» и существующие переходы к источнику и контролю качества.

**Критерии готовности:**
- Можно открыть и закрыть месяц, выбрать неделю и день в месячном календарном представлении и вернуться к годовому обзору без перезагрузки.
- Повторное нажатие на месяц, кнопка возврата и Escape корректно сворачивают детали; фокус клавиатуры не теряется.
- Статусы периода и показатели соответствуют выбранным реальным источникам; недельные и месячные суммы не подменяют дневные.
- Сетка корректна для 28/29/30/31 дня, переходов через год и недель на границе двух месяцев.
- Работают клавиатура, сенсорное управление, светлая и тёмная темы; нет горизонтального переполнения на экранах 320/390/768/1280 px.
- Автотесты охватывают открытие/закрытие, режимы, выбор недели и дня, пересечения дат, статусы, `aria-expanded` и управление фокусом.

## Этап 2 — контроль данных и защита от потерь (P1)

### 2.1. Умный предварительный просмотр

**Задача:** развить существующий предпросмотр, а не создавать второй экран импорта.

**Критерии готовности:**
- До сохранения показываются распознанные листы, подразделения, тип периода, даты, количество работ, дневные пары и контрольные итоги.
- Неподтверждённые значения выделены отдельно от достоверных; для замечаний есть понятный переход к ячейке/листу.
- Видно, что именно будет добавлено, заменено, пропущено или оставлено без изменений.
- Отмена предпросмотра ничего не записывает; конфликтные и неполные файлы не импортируются автоматически.

### 2.2. Автоматическое резервное копирование SQLite

**Задача:** добавить регулярные безопасные локальные снимки базы и восстановление без риска повреждения работающей базы.

**Критерии готовности:**
- Используется согласованный механизм резервного копирования SQLite (с учётом WAL), а не простое копирование открытого файла.
- Есть копия перед потенциально разрушительной массовой заменой, политика хранения ограниченного числа копий и отображение даты последней успешной копии.
- Восстановление требует подтверждения, сначала проверяет целостность, по возможности сохраняет текущую базу как откатную копию.
- Проверены сбой записи, нехватка места, закрытие во время операции и восстановление на копии пользовательских данных.

### 2.3. Понятное состояние источников и синхронизации

**Задача:** дополнить существующий календарь и контроль качества сводкой состояния *файлов-источников*.

**Критерии готовности:**
- Для каждого Excel виден статус: загружен, требует проверки, ошибка, устарел/изменён, недоступен или ожидает настройки.
- Показываются последняя успешная синхронизация и понятная причина сбоя.
- «Нет отчёта» и «явный ноль» не смешиваются; ошибка сканирования не стирает последний корректный набор.
- Есть переход к проблемному файлу и ручной повтор проверки.

### 2.4. Выявление пересечений между источниками

**Задача:** дополнить существующие проверки пересечений случаями, когда разные файлы дают данные одного подразделения за один период.

**Критерии готовности:**
- Конфликт определяется с учётом типа периода, дат, подразделения и идентичности источника.
- Автоимпорт не суммирует и не заменяет конфликтующие записи молча.
- Пользователь видит сравнение источников и может подтвердить безопасный вариант; сохранение выполняется атомарно.
- Проверены замена исходного файла, одинаковый период в двух файлах и корректный повторный импорт без дублей.

## Этап 3 — производительность больших массивов (P2)

### 3.1. Измерение и оптимизация SQLite + интерфейса

**Историческое состояние на 0.1.5:** защитные лимиты XLSX, Rust-парсер с временной SQLite и **постраничное чтение в отдельном SQL-режиме** ([методика](XLSX_LIMITS.md)). **В текущем `main`:** расширены нативные лимиты и добавлен потоковый импорт обычных XLSX. При этом классический интерфейс может загружать историю целиком; результаты на больших реальных наборах и потребление памяти от Rust до UI требуют измерения. Задача 3.1 не закрыта.

**Задача:** определить узкие места на большой истории, затем внедрять только обоснованные оптимизации.

**Критерии готовности:**
- Есть воспроизводимые измерения времени запуска, загрузки, фильтрации, построения графиков, импорта и использования памяти на больших синтетических данных.
- При подтверждённой необходимости — выборочные запросы SQLite, постраничная загрузка и кеширование агрегатов с корректным сбросом кеша.
- Результаты аналитики до и после оптимизации совпадают; сохранены проверки качества, группы и смешанные типы периодов.
- Интерфейс остаётся отзывчивым при импорте; нет скрытой потери или усечения данных.

## Общие условия принятия изменений

1. Каждую задачу выполнять отдельным проверяемым PR или небольшой логически связанной серией; не объединять с выпуском/изменением канала обновлений без отдельного решения.
2. Не менять расчёты, форматы Excel, SQLite или сохранённые правила без необходимости; если миграция действительно нужна — предусмотреть совместимость и откат.
3. Проверять регрессию браузерного интерфейса, Node-тесты, Rust-тесты SQLite и Windows CI. Для изменений Tauri дополнительно проводить ручной запуск в Windows/WebView2.
4. Для данных с замечаниями сохранять различие «нет данных / ноль / ошибка», запрет на неявную подмену и явное подтверждение опасных операций.
5. Историю импортов и сохранённые наборы фильтров не добавлять автоматически: ранее они были исключены из объёма работ и требуют отдельного решения.
6. Закрывать пункты плана только после фиксации PR, результатов тестов и оставшихся ограничений; наличие плана не означает готовность функции.
