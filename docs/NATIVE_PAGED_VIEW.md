# D4a — постраничный просмотр отчётов SQLite (эксперимент)

В Tauri-сборку добавлена отдельная раскрываемая панель «Постраничный просмотр SQLite» на экране загрузки. Автономный `index.html` не меняется.

- Две новые Tauri IPC-команды: `native_read_revision` и `native_report_page`. Запросы выполняются вне потока WebView. Используется уже существующая D1 модель SQLite: строгая ревизия, проверка длины заголовков, keyset-порядок `(period_start, id)`, ограничение 1–500 записей.
- JS запрашивает максимум **100 метаданных отчётов** за вызов (начало, конец, тип, имя источника, ID), хранит только текущую страницу и курсоры предыдущих страниц, показывает типы периодов. Значения выводятся через `textContent`, не через HTML. При устаревшей ревизии дальнейшая навигация блокируется до обновления.
- Команды **не возвращают JSON отчётов и не записывают пользовательскую базу**. Текущие импортер, настройки, графики и экспорт не затронуты.
- **Это ещё не полная оптимизация памяти:** старый стартовый `index.html` по-прежнему выполняет `desktopAPI.load()` / `load_data`, собирает полную историю в `state.reports` и делает полнообъёмные сохранения. Переключать этот путь до реализации безопасного полного CRUD/аналитического интерфейса и миграции резервного копирования нельзя.
- Проверьте в Windows GUI: экран загрузки → «Постраничный просмотр SQLite» → «Открыть список отчётов», фильтрация по типу, «Далее», «Назад», «С начала». Для проверки stale revision обновите тестовую SQLite из другого потока и убедитесь, что экран предлагает обновить список. Используйте только синтетические данные и изолированный профиль.
