# Репетиция восстановления SQLite на отдельной копии

**Статус:** инструмент проверки резервного файла перед выпуском Tauri 0.1.4. Это **не** замена активной базы внутри приложения. Утилита не изменяет исходную SQLite и не перезаписывает существующий файл назначения.

## Использование

Требуется Python 3.12. Из корня репозитория:

```powershell
python tools/restore_sqlite_copy.py "D:\Backups\analiz-backup.sqlite3" "D:\Backups\restore-check.sqlite3"
```

Первый путь — существующая резервная копия SQLite, второй — **новый** файл в уже существующем каталоге. Если путь занят, восстановление отменяется. Созданный файл предназначен для проверки **в отдельной папке**; не переименовывайте его в рабочую `Документы\Анализ работ\reports.sqlite3` при запущенном Tauri.

Программа проверяет `PRAGMA quick_check`, наличие таблиц `reports` и `kv` и корректность JSON. Через SQLite Online Backup создаётся консистентная копия, включая данные WAL. Проверяется SHA-256 схемы, отчётов и настроек на одном снимке до/после копирования. Временный файл переводится в самостоятельную базу без WAL и публикуется через жёсткую ссылку без перезаписи. При ошибке временные файлы удаляются. На томах без поддержки жёстких ссылок операция завершается отказом.

SQLite Online Backup переносит **все** таблицы, однако логический хеш проверяет только схему, отчёты и настройки; это не полная проверка аналитических значений остальных таблиц. Для них необходимы функциональные проверки приложения.

## Проверки надёжности восстановления

Python-тесты проверяют незавершённый WAL, BLOB JSON, дополнительные таблицы, отказ от перезаписи, повреждённые файлы и очистку временного хранилища. Они не зависят от версии предыдущего установщика.

```powershell
python -m unittest discover -s tests -p test_sqlite_restore_copy.py -v
```

Это проверка на синтетических данных. Она **не доказывает** восстановление произвольной базы или полноту аналитических итогов. При необходимости восстановления рабочей базы требуется отдельная безопасная процедура при закрытом приложении; прямую замену открытой SQLite не выполнять.

Совместимость установщика и миграция данных с 0.1.3 **не являются условиями выпуска**: приложение пока разрабатывается. Для новых данных остаются обязательными проверки целостности и отсутствие потери информации при сбоях.

## Проверка внутри Tauri (новый первый этап P0.3)

В исходниках Tauri предусмотрен интерфейс **«Проверить резервную копию» → «Создать отдельную восстановленную копию»**. Он не является частью опубликованной версии 0.1.5, пока соответствующий PR не пройдёт проверки, не будет включён в релиз и не появится в установщике.

1. В SQL-режиме откройте «Проверить резервную копию» и выберите существующий файл `.sqlite3`, **не** активную `reports.sqlite3`.
2. Rust выполняет `PRAGMA integrity_check`, проверяет таблицы `reports`/`kv`, JSON отчётов и настроек, внешние ключи и контрольный отпечаток. В интерфейсе появляется количество подтверждённых отчётов.
3. Нажмите «Создать отдельную восстановленную копию», подтвердите действие и укажите **новое** имя файла. Перед переносом повторно проверяется отпечаток, наличие свободного места, затем все таблицы копируются через SQLite Online Backup. Файл проверяется и публикуется без перезаписи существующих файлов.

**Это не восстановление рабочей базы.** Никаких переименований, замен или ручного копирования поверх открытой базы выполнять нельзя. Для реального возврата к копии всё ещё нужен отдельный механизм со штатным закрытием соединений, защитной копией текущих данных, переключением на старте и откатом при сбое.

Отпечаток текущего этапа проверяет схему и основные записи `reports`/`kv`. SQLite Online Backup сохраняет также дополнительные таблицы видов отчётов; проверка их логических агрегатов остаётся отдельным критерием перед разрешением подмены рабочей базы.

## Переключение рабочей SQLite при следующем запуске (следующий этап, отдельный PR)

После проверки резервного файла пользователь может нажать **«Восстановить рабочую базу при следующем запуске»** и подтвердить замену. Эта команда **не меняет активную базу**: Rust через SQLite Online Backup создаёт проверенную отдельную копию внутри каталога данных и записывает небольшой запрос на восстановление. Кнопка **«Отменить отложенное восстановление»** удаляет только запрос, не меняя SQLite.

При следующем **полном** запуске приложения, до создания `Storage` и соединений SQLite:

1. Приложение получает эксклюзивную межпроцессную блокировку файла запуска. Второй экземпляр этой версии не может одновременно открыть рабочую базу.
2. Rust повторно проверяет целостность подготовленной копии и контрольный отпечаток, проверяет свободное место, создаёт **проверенную отдельную защитную копию текущей рабочей базы** через SQLite Online Backup.
3. Перед перемещением текущей базы выполняется контроль WAL и закрытие собственного SQLite-соединения. Если остались `-wal`/`-shm` или другая программа использует SQLite, переключение прекращается без удаления данных.
4. Старая база **перемещается** в файл с уникальным именем внутри каталога данных; подготовленная копия занимает имя `reports.sqlite3`. Rust сверяет новый файл с ожидаемым отпечатком и проверяет доступность текущей схемы. Только после успешной проверки удаляется запрос на восстановление. **И прежняя база, и отдельная защитная копия сохраняются.**
5. Если процесс прервался после перемещения прежней базы, следующий запуск сначала пытается вернуть прежнюю SQLite. При неоднозначном состоянии запуск останавливается, чтобы не повредить данные. При ошибке до замены исходной базы приложение может открыться с предупреждением и дать отменить запрос.

**Ограничения:** блокировка действует для сборок с этой реализацией; старые экземпляры программы могут её не соблюдать, поэтому проверка WAL и отсутствие сторонних соединений обязательны. В случае остановленного запуска нельзя самостоятельно удалять служебные файлы или переименовывать SQLite: сохраните весь каталог данных для диагностики. Не обещать гарантированный откат при полном отказе диска/операционной системы без внешней резервной копии. После реализации необходимы тесты сценариев прерывания и Windows/WebView2; до успешного CI этот механизм не считается готовым для выпуска.
