# Восстановление личной SQLite и проверка отдельной копии

В текущем интерфейсе Tauri восстановление личной базы выполняется при следующем запуске после проверки файла и явного подтверждения. Вспомогательная Python-утилита создаёт отдельную проверочную копию. Ни один из этих сценариев не требует ручной подмены открытой SQLite.

## Восстановление через приложение

1. В «Управление → Базы данных» выберите личную базу и нажмите **«Проверить файл копии…»**. Выберите резервный `.sqlite3`, а не активную `reports.sqlite3`.
2. Сверьте показанное число отчётов в текущей базе и копии. Rust проверяет `PRAGMA integrity_check`, таблицы `reports`/`kv`, JSON, связи и контрольный отпечаток схемы и данных, включая дополнительные таблицы приложения.
3. Нажмите **«Восстановить при следующем запуске»** и подтвердите замену. Группы, справочник и настройки также будут взяты из копии. Ревизия личной базы и отпечаток выбранного файла проверяются повторно.
4. Закройте приложение и запустите его снова. До перезапуска доступна кнопка **«Отменить запланированное восстановление»**. Изменения, внесённые в личную базу после планирования, сохранятся в защитной копии перед заменой.

Подготовка создаёт проверенную отдельную копию внутри каталога данных и запрос на восстановление; активная база не заменяется. Отмена удаляет запрос, оставляя подготовленную копию. Этот пользовательский сценарий предназначен для личной базы; порядок работы с общей базой описан в [инструкции Tauri](../tauri/README.md#общая-база-сотрудников).

Реализация: [database-panel.html](../tauri/database-panel.html), [database-backups.js](../tauri/database-backups.js), [database/recovery.rs](../tauri/src-tauri/src/database/recovery.rs), [database/activation.rs](../tauri/src-tauri/src/database/activation.rs).

## Переключение при следующем запуске

До открытия рабочей области приложение получает эксклюзивную межпроцессную блокировку и обрабатывает запрос восстановления:

1. Повторно проверяет целостность и отпечаток подготовленной копии, текущую базу и свободное место.
2. Создаёт **проверенную защитную копию текущей базы** через SQLite Online Backup, завершает её без WAL и сверяет содержимое.
3. Перед перемещением текущей базы проверяет WAL/SHM и неизменность исходных данных. При занятых файлах или неоднозначном состоянии переключение останавливается.
4. Перемещает прежнюю базу в файл с уникальным именем, устанавливает подготовленную копию как `reports.sqlite3`, проверяет отпечаток и открытие текущей схемы. Запрос удаляется только после успешной проверки; **прежняя база и защитная копия сохраняются**.
5. При прерывании после перемещения прежней базы следующая попытка запуска сначала возвращает её. Если состояние нельзя однозначно восстановить, запуск останавливается. Ошибка подготовки до перемещения может позволить открыть исходную базу с предупреждением и отменить запрос.

Блокировка действует для экземпляров с этой реализацией; сторонняя программа или старая сборка может её не соблюдать. При остановленном запуске не удаляйте служебные файлы и не переименовывайте SQLite вручную: сохраните каталог данных для диагностики. При полном отказе диска или ОС механизм не заменяет внешнюю резервную копию.

## Отдельная проверочная копия через Python

Утилита [restore_sqlite_copy.py](../tools/restore_sqlite_copy.py) не переключает базу приложения, не меняет исходную SQLite и не перезаписывает существующий файл назначения. Для запуска используется Python 3.12; из корня репозитория:

```powershell
python tools/restore_sqlite_copy.py "D:\Backups\analiz-backup.sqlite3" "D:\Backups\restore-check.sqlite3"
```

Первый путь — существующая резервная копия, второй — **новый** файл в существующем каталоге. Утилита проверяет `PRAGMA quick_check`, таблицы `reports`/`kv` и JSON, переносит все таблицы через SQLite Online Backup, включая WAL, и публикует самостоятельную копию без WAL через жёсткую ссылку без перезаписи. На томе без поддержки hard links операция завершается отказом.

**Ограничение этой утилиты:** её логический SHA-256 проверяет схему, отчёты и настройки, но не содержимое остальных таблиц. Нативная проверка Tauri дополнительно включает эти таблицы в отпечаток. Ни одна проверка целостности не доказывает правильность всех аналитических итогов; для них нужны функциональные проверки.

## Проверки и история

[Python-тесты](../tests/test_sqlite_restore_copy.py) проверяют WAL, BLOB JSON, дополнительные таблицы, отказ от перезаписи, повреждённые файлы и очистку временного хранилища:

```powershell
python -m unittest discover -s tests -p test_sqlite_restore_copy.py -v
```

Нативные тесты находятся в `database/recovery.rs` и `database/activation.rs`, UI-проверки — в [database-backups.test.cjs](../tauri/tests/database-backups.test.cjs). Для приёмки изменений нужны проверки отказов, прерываний и Windows/WebView2 на конкретном SHA по [CODEX_SAFETY_RULES.md](CODEX_SAFETY_RULES.md) и [RELEASE_POLICY.md](RELEASE_POLICY.md). Наличие тестов не означает их успешного выполнения на текущем коммите.

Прежние редакции документа описывали утилиту перед 0.1.4 и отдельный этап создания копии для 0.1.5. Это история разработки, а не ограничение нынешнего интерфейса. Обратная совместимость со старыми экспериментальными выпусками, включая 0.1.3, не является условием выпуска; целостность текущих данных и отсутствие несанкционированной потери файлов остаются обязательными.
