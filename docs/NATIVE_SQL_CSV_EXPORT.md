# D4f — нативный экспорт CSV из SQLite

Экспериментальный SQL-режим Tauri дополнен кнопкой **«Экспорт CSV»** после успешного расчёта. Источник — существующая D2 функция `analysis_export_range`, а не `state.reports` или синхронная сборка CSV в браузере.

- Выбор файла через Tauri `dialog.save`; пользователь явно указывает папку и имя. Сам выбор файла **не запускает экспорт**: только последующее выполнение нативной команды делает запись.
- IPC `native_export_range_csv` выполняется в `spawn_blocking`, проверяет ревизию, тип периода, дату (не более 3660 дней), 1–100 организаций и включённость выбранного подразделения в этот набор. При нарушении входных данных ошибка без записи.
- D2 пишет CSV с UTF-8 BOM и разделителем `;`, защищает от формульных значений в Excel и сохраняет пустые ячейки для неизвестных количеств и сумм. Файл сначала записывается во временное место в **том же каталоге**, синхронизируется, затем атомарно связывается с целевым именем. **Существующий файл никогда не заменяется**; если целевое имя занято, нужно выбрать другое.
- Во время выбора файла и записи временно блокируются действия, изменяющие параметры анализа; при их последующем изменении результаты и право экспорта сбрасываются. Отмена диалога не изменяет SQLite и не создаёт CSV.
- Node-тесты покрывают задержку до выбора файла, параметры и жизненный цикл IPC; установленный WebView2 smoke выгружает пустую недельную выборку после 366 синтетических дневных отчётов, проверяет BOM/заголовок и отказ от перезаписи.
- **Ограничения:** сохранение общего CSV-анализа не является резервной копией SQLite и не воспроизводит исходный Excel. Это read-only функция поверх отдельного SQL-режима; стандартный запуск пока использует прежний интерфейс. Расширенные CSV сравнения и нативный импорт с подтверждением качества остаются дополнительными работами. Не выпускать новую рабочую версию до полной проверки реальных данных и процедуры восстановления.
