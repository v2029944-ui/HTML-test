# Дневные данные за квартал или год

Новый формат сосуществует с обычными горизонтальными тройками. Основной HTML остаётся одним автономным файлом; Electron и Tauri используют те же функции импорта. Недельные, месячные и прежние дневные отчёты сохранены. Квартал и год — формат источника, а не новые типы аналитических периодов: каждая достоверно заполненная пара создаёт отчёт `day`.

## Структура и распознавание

Один общий столбец содержит подразделения и работы. Остальные столбцы идут парами количества и суммы по дням; последняя пара может содержать итоги источника. Метки количества/суммы, даты над ними и столбец работ распознаются по содержимому, а не по фиксированной строке. Учитываются объединения заголовков. Повторяющиеся столбцы работ старого формата не считаются общим столбцом нового формата.

Поддержаны полные ISO и российские числовые даты, сокращённые день/месяц с подтверждённым годом, русские названия месяцев, отдельные строки месяца и числа, числовые даты Excel (включая систему 1904 при соответствующем свойстве книги). Для короткого двузначного года требуется подтверждённый век. Несуществующие даты, разные даты над количеством и суммой, повторные дни внутри листа или между выбранными листами блокируются. Итоговые пары должны иметь понятную метку либо быть указаны вручную; неизвестный столбец не превращается в следующий день по догадке.

Книга может содержать один широкий годовой лист либо квартальные листы. По умолчанию выбираются все найденные подходящие листы. Можно явно выбрать подмножество. При неоднозначном годе требуется ввод пользователя; имя листа не является единственным основанием распознавания. Для непонятной структуры выберите новый формат и включите ручную настройку нужного листа: столбец работ, строка заголовков, первый столбец дневного количества и оба итоговых столбца. Столбцы вводятся буквами Excel, строка — обычным номером с единицы.

Не распознаются произвольные нестандартные макеты и формулы без сохранённых числовых результатов: встроенный читатель не вычисляет формулы. Реальный квартальный/годовой образец не предоставлен, поэтому соответствие неизвестному файлу не гарантируется; диагностика и ручная настройка обязательны для отличающихся шапок.

## Пустые значения, нули и итоги

Полностью пустая дневная пара не создаёт отчёт. Отдельные пустые пары в строках услуг пропускаются без фиктивных нулевых выполнений. Один непустой некорректный показатель пары сохраняет диагностическую проблему с реальными координатами. Число `0` — значение. Нулевой день без строк работ допустим только при явно нулевых контрольных итогах подразделений/общем итоге; он помечается `explicitZero`.

Дневные итоги подразделений сверяются существующим `parseSheet`; строки подразделений и «Итого» не становятся работами. Сумма доступных дневных значений каждой строки дополнительно сверяется с итоговой парой квартала/года. Итоговые столбцы никогда не становятся отдельным днём. Координаты контрольных ячеек относятся к исходному Excel; финансовые значения автоматически не исправляются.

Полный список замечаний хранится у первого импортированного дня соответствующего листа; остальные дни содержат ссылку `sourceControlDate`, чтобы календарь не показывал их как полностью проверенный источник. Отдельные ссылки ведут к качеству выбранного дня и к исходным итогам. Для выбранного пустого исторического листа с замечаниями или ненулевыми итогами останавливается весь импорт — его нельзя незаметно исключить из замены. Пользователь может явно снять выбор такого листа.

## Ручной и автоматический импорт

В браузере используется обычный выбор файла, затем «Проверить Excel» и «Сохранить отчёты». Для годового файла предпросмотр ограничен первыми 31 днями, подробные замечания доступны в контроле качества. Сохранение при замечаниях требует подтверждения, а не нажатия одной автоматической кнопки.

В настольном блоке «Папка Excel» добавлены формат, год и выбор листов. «Автоматически» определяет общие дневные столбцы, сохраняемое правило использует `format: daily-wide`. Автоимпорт обрабатывает все выбранные листы, а не первый. Пользователь может открыть существующий предпросмотр через «Проверить и сохранить вручную», изменить столбцы и нажать «Запомнить настройки файла для автоимпорта».

Автоматический импорт отклоняет любое замечание, ошибку, повторный день или конфликт источников и сохраняет прежний снимок файла. Изменение файла во время чтения/разбора проверяется по сигнатуре. Один файл заменяется целиком одним вызовом сохранения; SQLite выполняет его транзакционно. При ручной замене связанного источника требуется флажок замены: удаляются только прежние дни этого же источника и добавляется весь новый набор. Источник из другой известной папки защищён от тихой замены даже при совпадении имени файла. Старые отчёты без метаданных папки сохраняют совместимость прежнего правила имени источника.

Удаление XLSX и временная недоступность папки не удаляют сохранённые отчёты. После восстановления доступа слежение повторяет синхронизацию (исправление PR #11 сохранено). Время последней успешной синхронизации берётся из сохранённых дат импорта. Файлы правил не содержат закрытые ключи обновлений.

## Календарь

Основное представление — 12 месяцев выбранного года, независимо от типов загруженных отчётов. Год выбирается напрямую из списка или соседними кнопками. Нажатие месяца открывает сетку дней и переводит к ней экран; есть возврат к списку месяцев. День раскрывает источник, лист, подразделения, доступные показатели и качество.

Подтверждённые пропуски определяются в заявленном диапазоне источника либо между загруженными дневными отчётами. Будущие дни не считаются пропущенными. Отсутствие подтверждённого покрытия показывается нейтрально. Зелёный означает доказанную полноту без существенных замечаний; красный — ошибки или установленную неполноту; предупреждающий цвет — смешанные источники или неподтверждённое качество.

Дневные, недельные и месячные источники показаны раздельно. Количество и сумма дневных отчётов не складываются с месячными. Месячный источник имеет отдельные итоги. Недели через границу месяца показываются целиком в источниках без распределения суммы по дням. Спорные пересекающиеся данные исключаются; доступная часть подписана как часть, а не полный месячный результат. Список сохранённых отчётов ограничен 50 строками на страницу с прямым выбором страницы. Подробные источники раскрываются порциями.

Поля найденных файлов имеют подписи сверху, одинаковую высоту и используют существующие цвета, размеры и скругления. На узких экранах кнопки переходят на отдельные строки; имена и сообщения переносятся.

## Пределы и совместимость

- До **2048 столбцов** вместо молчаливого обрезания на 500; год с 366 днями и итогами содержит 735 столбцов.
- До 60 000 строк листа, 1 500 000 заполненных ячеек книги, 20 000 объединений на листе.
- Прежний предел 48 МБ на распакованный XML-компонент; дополнительно 192 МБ на сумму распакованных компонентов книги. Ограничения размеров исходных файлов не увеличены.
- Слишком широкая, большая или повреждённая книга отклоняется с диагностикой, а не частично импортируется.
- JSON/SQLite остаются версии 1. Новые правила имеют необязательные `format`, `year`, `sheets`, `mappings`; старые правила сохраняют три прежних поля. Порядок ключей Rust HashMap не меняет идентичность нового правила.
- Миграция исходных `reports.json` и `desktop-config.json` не удаляет файлы. Структура таблиц SQLite не менялась; полного рефакторинга хранения не потребовалось.

## Проверки

```
node --test tests/*.cjs tauri/tests/*.test.cjs desktop/core.test.cjs
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -v
cargo test --manifest-path tauri/src-tauri/Cargo.toml
```

Синтетические XLSX: 365/366 дней, один годовой и четыре квартальных листа, более 500 колонок, шапка после служебных строк, объединения, текстовые/числовые даты, неоднозначный год, пустые и нулевые дни. Node дополнительно проверяет неверные даты, повторы, перестановку дней, ручное сопоставление, несовпадающие даты пары, пустой лист с ненулевыми итогами и стабильность правил. Модель 500 услуг ×366 дней (183 000 строк итоговых дневных отчётов) разбирается примерно за 3–6 секунд в текущем Linux-окружении; это не замер Windows GUI или универсальная гарантия скорости. Отдельно реально прочитан сжатый синтетический XLSX на 735 столбцов и 500 услуг/день: 864 443 байта, 366 дней, 183 000 строк; загрузка и предпросмотр в Chromium заняли 6,38 секунды.

Проверена регрессия старого частного `Анализ.xlsx`: три недельных набора, справочник, сохранение и повторное открытие, итоги и среднее диапазона сверены с исходными строками. Сам Excel не менялся и не включён в репозиторий. Проверены 320/390/1280 px, просмотрены светлые/тёмные скриншоты файлов и мобильного календаря. Физический iPhone/Safari и работа реального нового квартального/годового файла на Windows не проверены.

Статусы Rust и Windows CI фиксируются в PR после выполнения: наличие тестов не означает, что они уже запущены. Выпуск и слияние PR не выполняются без отдельного поручения.
