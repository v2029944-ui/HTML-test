# Переход интерфейса Tauri на SQLite — этапы 1–4

**Статус: безопасный переключаемый запуск SQL-режима.** Этот этап ещё не означает, что вся аналитика и весь импорт переведены на SQL.

## Цель

Постепенно сделать SQLite основным источником данных и вычислений в Tauri, не потеряв работающие функции «Анализа работ». Сохранить исходный `index.html` как автономную браузерную версию.

В исходном интерфейсе Tauri старый вызов `load_data` может загружать все отчёты в память WebView. Отдельный `native-workspace.html` запрашивает только ограниченные порции данных, а агрегации выполняет Rust/SQLite. Переход должен исключать такой полный `load_data` при запуске SQL-режима.

## Что реализовано на этом этапе

- Системное окно Tauri начинает с лёгкой страницы `startup.html` и внешнего скрипта `tauri-startup.js`. Ни та, ни другой **не импортируют**, не читают и не сохраняют полный JSON истории.
- По умолчанию программа перенаправляет в **прежний** `index.html`. Это необходимо, потому что некоторые операции и графики ещё доступны только там.
- В SQL-режиме есть настройка **«Открывать SQL-режим при запуске программы»**. После её включения следующие запуски ведут непосредственно в `native-workspace.html`, без запуска классического интерфейса.
- Настройка хранится под ключом `analiz-sql-startup-v1` в локальных предпочтениях WebView2 и не затрагивает SQLite. Снять галочку можно там же. Ссылка на классический интерфейс и импорт Excel всегда остаётся доступной.
- Если локальное хранилище недоступно, приложение безопасно открывает классический интерфейс, а настройка блокируется. Если автоматический переход невозможен, на стартовой странице есть прямые ссылки на оба интерфейса.
- Автономный `index.html`, форматы импорта, схема SQLite, путь пользовательской базы и алгоритмы вычислений этим PR не изменяются. Номер версии не увеличивается; отдельный релиз готовится только после полного CI и разрешения владельца.

## Как проверить

1. Установить **сборку, содержащую этот PR**, и открыть «Управление → Отчёты → Перейти в отдельный SQL-режим».
2. Включить «Открывать SQL-режим при запуске программы».
3. Закрыть программу обычным способом и открыть снова. Должен появиться SQL-режим с ограниченным чтением; `window.appReady` классического интерфейса здесь не создаётся.
4. Перейти по ссылке **«Классический интерфейс и импорт Excel»**. Проверить доступность прежнего импорта и данных.
5. Снять настройку в SQL-режиме, закрыть и запустить программу повторно. Должен открыться привычный интерфейс.

**Автоматические проверки:** `tauri/tests/sql-startup.test.cjs` проверяет маршрутизацию, сохранение настройки, отсутствие полного bootstrap на лёгкой странице, недоступность локального хранилища и соответствие реальной конфигурации. `tauri/tests/windows_smoke.py` дополнительно проверяет путь SQL-first на установленном приложении с WebView2 и возврат к классическому интерфейсу.

## Этап 2 — источники Excel и актуальность сводки SQLite

В отдельном SQL-режиме появилась панель **«Папка Excel»**. Через существующие Rust-команды `list_excel` / `set_folder` она показывает только имена, размер и наличие настроенного правила для первых 100 файлов. Содержимое XLSX и полная история отчётов в JavaScript не загружаются; изначальный API Rust по-прежнему возвращает метаданные всего каталога, поэтому ограничение 100 относится только к отображению, не к размеру результата IPC.

- Если выбрана другая папка, программа до открытия диалога предупреждает, что сохранённые правила для прежнего каталога будут сброшены. Уже импортированные отчёты не удаляются. После смены папки SQL-режим автоматически обновляет ревизию базы, чтобы не продолжать расчёты со старой ревизией.
- Пока SQL-режим открыт, изменение состава папки обнаруживается существующим Tauri-поллингом. **Ничего не импортируется автоматически**, новые файлы видны в списке после обновления. Автоимпорт обычных книг пока остаётся в классическом интерфейсе. Простейшие правила можно редактировать в SQL после этапа 3.
- После **успешной нативной записи широкого XLSX** SQL-режим автоматически перечитывает ревизию, заголовки текущей страницы и настройки из SQLite, не вызывая `load_data`. Старая аналитика сбрасывается, чтобы не показывать устаревшие итоги. Если обновление экрана не получилось, сохранение не объявляется неуспешным: выводится предложение обновить вручную.
- Прямое редактирование исходных XLSX, удаление отчётов при удалении файла и автоматический импорт без предпросмотра **не добавлены**. Сохраняются подтверждения замен и гарантии резервного копирования.

Проверки: `tauri/tests/native-folder-status.test.cjs`, новые сценарии в `tauri/tests/native-wide-import.test.cjs` и установленный WebView2 в `tauri/tests/windows_smoke.py`.

## Этап 3 — изменение правил Excel без полной загрузки истории

В панели «Папка Excel» добавлен редактор правил для первых 100 файлов. Пользователь явно выбирает XLSX, тип периода, формат, дату первого периода и при необходимости лист или год. Простые правила обычных, автоматических и широких дневных таблиц настраиваются без открытия классического интерфейса. Существующие расширенные сопоставления листов и столбцов защищены от случайной потери: их изменение по-прежнему доступно только в классическом интерфейсе.

- Rust-команда `native_set_rule_checked` **отказывает в сохранении**, если с момента просмотра изменилась ревизия SQLite, исходная папка или метаданные XLSX. Путь проверяется: файл должен быть обычным (не символической ссылкой), иметь безопасное имя и не превышать 30 МБ. После успешной записи обновляется ревизия SQL-аналитики.
- `list_excel` возвращает ревизию в том же снимке, что и метаданные источников и правила. Данные из XLSX в JavaScript не передаются.
- Проверка состояния XLSX при сохранении правила использует размер и временные метки файла, **не криптографический хеш содержимого**. Поэтому она предотвращает типичные устаревшие изменения, но не является подтверждением корректности файла. Реальный импорт должен повторно проверять хеш и состав данных в Rust перед транзакционным сохранением.
- Сохранение правила требует нажатия пользователя и подтверждения; оно **не запускает импорт**. Оно может повлиять на автоматический импорт, если открыт классический интерфейс. Оповещения об изменении папки в SQL пока только обновляют список.

Тесты: Rust-тест `checked_rule_saves_only_for_current_sql_revision_folder_and_file`, `tauri/tests/native-folder-status.test.cjs` и проверка IPC в `tauri/tests/prepare.test.cjs`. Полный Windows CI также должен проверить установленный Tauri/WebView2.

## Этап 4 — ручной импорт обычных XLSX через Rust без полной истории

В SQL-режиме добавлен отдельный **нативный импорт обычной таблицы с повторяющимися тройками «Работа / Количество / Сумма»**. Пользователь выбирает XLSX, вводит **точное название листа**, тип периода (день/неделя/месяц) и дату первого периода.

- Rust `analiz-import-core::Stage::convert_legacy` потоково читает XLSX в временную SQLite, преобразует обычные колонки и готовит проверяемый пакет отчётов. JavaScript получает только ограниченный список итогов и замечаний; не вызывается полная загрузка истории.
- Предпросмотр подписывается отдельным токеном от хеша исходного файла, настроек, ревизии SQLite, плана конфликтов и результатов парсинга; повторный вызов перед сохранением должен получить идентичный токен. Токены широкого и обычного импорта имеют разные области использования.
- Пользователь отдельно подтверждает замену существующих периодов, пересечения разных типов и проблемы качества. Если есть замены, Rust перед изменением SQLite создаёт проверенную резервную копию. Запись атомарна, повторно проверяет актуальность источника и ревизии.
- После подтверждённой записи экран обновляет только ограниченные SQL-данные. Ошибка обновления экрана не превращается в сообщение о неуспешном импорте.
- **Ограничения:** для автоматического распознавания троек нужно точно указать название листа с соответствующими заголовками; ручной маппинг сложных таблиц пока остаётся в классическом режиме. Пока это **ручной** импорт: фоновые изменения папки только обновляют список XLSX. Не поддерживаются автоматическая перезапись, удаление старых отчётов при удалении файла или автоматический импорт без проверки.

Node-проверки: `tauri/tests/native-legacy-import.test.cjs`. Rust-проверки и установленный Windows WebView2 должны пройти полный CI до включения этого этапа в основную ветку.

## Следующие этапы

1. Подключить **безопасную автоматическую обработку изменений XLSX** на основе уже существующего нативного ручного импорта: отдельный контроль источников, запрет неподтверждённых замен, инкрементальные пакеты и журнал изменений. Пока фоновое сканирование только сообщает о новых и изменённых файлах, но не пишет отчёты.
2. Перенести в SQL-режим все используемые фильтры, отчёты и графики. Расчёты должны совпадать на контрольных данных; значения при неполных периодах нельзя подменять нулём.
3. Унифицировать внешний вид интерфейса, убрать дублирование JavaScript/Rust-расчётов и проверять использование памяти на больших базах.
4. **Только после достижения функционального паритета** сделать SQL-режим запуском по умолчанию, оставив понятный путь для восстановления и диагностики.

Обратная совместимость между экспериментальными версиями не обязательна. Защита текущих данных, резервное копирование и проверка отсутствия потерь обязательны на каждом этапе.
