# Подписанные онлайн-обновления Tauri

Выпуски подписываются **одной постоянной парой ключей**. Для каждой новой версии ключи генерировать не требуется. Закрытый ключ никогда не помещают в публичный репозиторий, артефакты или логи. Публичный ключ используется в сборке для проверки подписанных обновлений.

## Релиз 1.5.1

Первый подписанный выпуск после 0.1.5 готовится отдельно из изменений, уже вошедших в `main`. Переход с неподписанной 0.1.5 выполняется вручную. В дальнейшем новые версии, подписанные той же парой ключей, смогут обновляться через приложение. Версию 1.5.1 публикует однократный workflow только после успешного Windows CI точного коммита одобренного релизного PR.

## Что уже имеется

16 ноября 2026 года успешно прошла [подписанная сборка Tauri](https://github.com/v2029944-ui/HTML-test/actions/runs/43935752959); опубликованный выпуск `tauri-v0.1.2` содержит установщик и `.sig`. Это доказывает, что ключи были доступны GitHub Actions тогда, **но не подтверждает, что Secrets не изменились позднее**.

Существующие имена GitHub Actions Secrets:

- `TAURI_SIGNING_PRIVATE_KEY` — закрытый ключ Tauri Updater (обязателен).
- `ANALIZ_UPDATER_PUBLIC_KEY` — открытый ключ той же пары (обязателен).
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль, если ключ защищён паролем (может быть пустым для ключа без пароля).

Проверьте наличие в GitHub **Settings → Secrets and variables → Actions**. Значения показывать, отправлять в чат или помещать в PR **не нужно**. Открытый ключ не является секретом, но пока используем существующее имя переменной для совместимости с уже настроенным workflow.

## Проверка старого ключа — без публикации

**При первом попадании workflow в `main` проверка запустится автоматически**, поскольку этот файл изменился. Это только проверка ключей на Ubuntu: Windows-установщик не собирается, выпуск не публикуется, `tauri-updates` не меняется. Найдите результат в **Actions → Tauri signed Windows release**.

Проверку также можно повторить вручную:

1. После попадания workflow в `main` откройте **Actions → Tauri signed Windows release → Run workflow**.
2. Выберите `main` и действие `check-keys` (по умолчанию). Поле версии оставьте пустым.
3. Workflow на Ubuntu проверит наличие ключей и сверит идентификатор открытого ключа с публичной подписью выпуска `tauri-v0.1.2`. Он **не собирает Windows-приложение, не публикует релиз и не меняет `tauri-updates`**.
4. Если результат `check-keys` успешен, открытый ключ совпадает с прежней подписью. **Соответствие закрытого ключа подтверждается дополнительно при сборке и подписи нового выпуска**; идентификатор проверяется повторно перед публикацией. Эта проверка идентификаторов не заменяет полноценную криптографическую проверку Tauri при установке.

Если отсутствует secret, восстановите **старое** значение из своей безопасной копии. Не генерируйте другую пару без отдельного решения о смене ключей.

## Новый выпуск без повторного создания ключей

1. Подготовьте новый номер версии **одинаково** в `tauri/package.json`, `tauri/src-tauri/Cargo.toml` и `tauri/src-tauri/tauri.conf.json` (например, `1.5.2`). Не используйте опубликованные ранее номера или теги. Создайте фактическое описание изменений в `tauri/release-notes/<версия>.md`.
2. Объедините проверенные изменения в `main`. Дождитесь успешного **Tauri 2 Windows (experimental)** CI на точном коммите `main`.
3. После отдельного разрешения владельца откройте **Actions → Tauri signed Windows release → Run workflow**, задайте `operation=publish` и точный номер в поле `version`. Это явное подтверждение публикации.
4. GitHub Actions автоматически использует **те же Secrets**, проверяет номер/заметки/CI/подпись, повторяет Rust/Node/SQLite/GUI-тесты, собирает NSIS, проверяет подписанный установщик, публикует отдельный GitHub Release и лишь затем переключает манифест `tauri-updates`. При ошибке проверки канал не должен переключаться.

`tauri/release.cjs` использует временную конфигурацию, которая добавляет публичный ключ именно в подписанную сборку; пустое поле `pubkey` в обычном `tauri.conf.json` **не означает**, что подписанный установщик останется без ключа. Прежние неподписанные сборки, включая `0.1.5`, не смогут сами обновиться через Tauri Updater: первую подписанную версию необходимо установить вручную. В дальнейшем обновления будут предлагаться в самом приложении.

**Не меняйте `tauri-updates` на 0.1.5:** его NSIS выпущен без Tauri-подписи. Сохраняйте резервную копию SQLite перед новой установкой. Программа в разработке, обратная совместимость между экспериментальными версиями не обязательна, но сохранность текущих данных — обязательна.

Полный выпуск регулирует [RELEASE_POLICY.md](RELEASE_POLICY.md). Официальная документация: https://v2.tauri.app/plugin/updater/.
