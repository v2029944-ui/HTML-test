# Привычный интерфейс поверх SQLite

Основание: пользователь просит отчёты, интерфейс и настройки как в Excel-версии с ранее внесёнными исправлениями, установленную версию и анимацию загрузки. Эталон — текущий index.html, включая меню «Управление» справа, независимые тему/палитру/дизайн/масштаб, исправления фильтров, графиков и контраста. Основной режим остаётся SQLite.

Переносим оболочку и настройки, используя исходные CSS и код оформления классической версии при подготовке Tauri. Сохраняем SQL API, постраничность, неполные данные, пропуски и безопасные операции. Не встраиваем классический renderer или полную историю JSON. Общий фильтр доступен для аналитики и анализа изменений. Календарь показывает 12 месяцев и раскрывает дни; список отчётов использует понятные названия типов и даты, технический ID уходит в отдельное раскрытие. Импорт доступен из отчётов и верхней кнопки.

Настройки включают оформление, базу/резервные копии, стартовый режим и обновления. Версия берётся из Tauri app.getVersion. Индикатор загрузки отражает все реальные tracked IPC, остаётся виден до завершения параллельных операций и снимается при ошибках; без вымышленного процента, с reduced-motion.

Календарь агрегирует только SQL-метаданные по датам начала отчётов, максимум 366 строк на год. Наличие отчётов не выдаётся за подтверждённое качество или полноту. Старые исправления скрытия подтверждённых нулей, сохранения пропусков и отсутствия вложенной вертикальной прокрутки сохраняются. Не слитый PR65 рассматривается как требования к календарю и расположению импорта, а не как уже принятый код.

Подход: общие визуальные исходники + SQL-представления. Ручное дублирование всей классической страницы расходилось бы с исправлениями; возврат к её полной загрузке истории нарушал бы цель перехода SQLite.
