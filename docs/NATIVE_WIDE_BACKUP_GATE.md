# E3 — обязательная резервная копия перед заменой отчётов

Дополнение к [нативному XLSX-импорту](NATIVE_WIDE_REVIEWED_IMPORT.md) и [проверенной SQLite-копии](NATIVE_SQLITE_BACKUP.md).

Когда C3 предварительный просмотр показывает `conflicts.replacements > 0`, веб-интерфейс **не допускает подтверждённую запись до успешного создания отдельной SQLite-копии**. После подтверждения пользователем открывается стандартный диалог сохранения `.sqlite3`. Отмена означает отказ от импорта; ранее проверенные отчёты не меняются. Текущая ревизия сохранённой копии сравнивается с ревизией предварительного просмотра; несоответствие требует заново проверить источник и условия замены. Временная копия/целевая публикация защищены D4g проверкой и запретом перезаписи.

После успешного создания копии C3 всё равно повторяет потоковую подготовку XLSX, проверяет исходник, планы конфликтов, качество, ревизию и перед записью выполняет атомарную транзакцию. Эта UX-защита добавляет независимый барьер перед заменой: даже при наличии `replaceExact` и пользовательских подтверждений импорт не начинается, если копия не создана.

Новые отчёты **без замен** не требуют обязательного предварительного снимка. Для них используются те же подтверждения качества и backend-проверки. Внешние Tauri IPC вызовы, не проходящие через интерфейс, всё ещё должны обеспечивать собственные резервы/политику безопасности; данный барьер относится к SQL-странице. Восстановление из резервной копии в работающей программе не поддерживается. Не заменяйте `reports.sqlite3` вручную при открытом Tauri.

## Server-side enforcement (E3b)

Дополнительно **сам Rust IPC `native_wide_import_apply`** отклоняет замену отчётов без `confirmation.backupDestination`. Он не доверяет флагу «копия создана», а самостоятельно вызывает `Storage::backup_sqlite_verified` перед C3-транзакцией, проверяет ревизию снимка, а при ошибке/запретах не применяет импорт. Одновременно подтверждаются замены, пересечения и качество. UI только выбирает имя файла — не может обойти требование копии. Windows WebView2 smoke проверяет прямой обход UI без backupDestination (должен быть отказ), успешный импорт с новой копией и целостность снимка старых 366 отчётов.
