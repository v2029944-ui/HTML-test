# D4d — сравнение подразделений в нативной SQL-аналитике

**Исторический этап.** Ниже описано состояние при первоначальном добавлении этой возможности. С 1.6.1 SQLite — основной экран; текущие возможности и проверки приведены в [статусе SQL-интерфейса](SQL_PRIMARY_WORKSPACE.md). Реальные рабочие книги остаются отдельной проверкой.

Отдельный режим Tauri теперь отображает таблицу и горизонтальные диаграммы по подразделениям для уже выбранных типа периода, дат и списка из `orgNames`. Источник — D2 `analysis_organization_page`; старый `index.html` и `state.reports` в этом режиме не загружаются.

- Новый IPC `native_analysis_organizations` использует `spawn_blocking`, SQL-фильтр подразделений из 1..100 строк, ревизию базы и строгую проверку дат (максимум 3660 дней); результат ограничен **100 подразделениями**. Фильтр удаляется и при ошибке.
- Для каждого подразделения D2 возвращает `complete`, количество пропущенных периодов и `total.count`/`total.amount`/`total.average`. Неполные ряды показывают «—» вместо вымышленных нулевых сумм. Полные ряды сортируются по подтверждённой сумме; относительная длина диаграммы показывает модуль суммы, знак сохраняется числом и цветом (синий для положительных, фиолетовый для отрицательных), **не обозначает «хорошо» или «плохо»**. Числа и названия вставляются только через `textContent`.
- Выбор другого подразделения, дат или типа сбрасывает старые результаты, чтобы не показывать их с новым фильтром. Изменившаяся ревизия отклоняет повторный SQL-расчёт; новый расчёт нужен после перезагрузки.
- Сравнение ограничено доступными в настройках `orgNames`. Другие исторические подразделения, которые не представлены в настройках, пока не выбираются. Индексирование D2 и список отчётов остаются порционными. Это не перенос полного графического интерфейса и не изменение обычного запуска программы.
- Проверки включают JS-данные с одной полной и одной неполной организацией, отсутствие ложного нуля, безопасное кодирование текста, реальный WebView2 с 366 тестовыми дневными отчётами и пустой недельной выборкой. До успешного CI и проверки реальных баз не включать по умолчанию.
