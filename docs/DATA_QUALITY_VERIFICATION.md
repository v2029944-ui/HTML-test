# Воспроизведение проверок данных P0

Статусы задач и ссылки на проверенные коммиты ведутся в [плане #79](https://github.com/v2029944-ui/HTML-test/issues/79). Тесты создают книги и базы во временных каталогах. Используйте отдельный профиль приложения и временную общую папку. Правила работы с данными описаны в [CODEX_SAFETY_RULES.md](CODEX_SAFETY_RULES.md).

## Синтетические сценарии

| Сценарий | Что сверять | Где создаются данные |
| --- | --- | --- |
| Число в количестве и пустая сумма | Количество сохраняется, сумма остаётся `null`. Явная сумма `0` остаётся числом. Некорректное содержимое имеет координаты исходной ячейки. | [`import-core/tests/reports.rs`](../tauri/import-core/tests/reports.rs), [`import-core/tests/wide.rs`](../tauri/import-core/tests/wide.rs) |
| Неполный диапазон, один или два | На одном наборе фильтров сравнить сводку, анализ изменений, CSV и печать. В установленном сценарии доступны сумма 20 и количество 2. При отсутствии сопоставимой пары разница и процент пусты. Дневные, недельные и месячные источники проверяются отдельно. | [`reference_data_smoke.py`](../tauri/tests/reference_data_smoke.py), [`analytics_tests.rs`](../tauri/src-tauri/src/analytics_tests.rs) |
| Дневные пары за квартал или год | При заголовках сверить даты обеих ячеек пары. Для последовательных пар задать год и квартал по листам вручную. В тестах Q1 содержит 90 или 91 день, год 365 или 366. Пустой день, явный ноль и контрольный итог источника различаются. | [`import-core/tests/wide.rs`](../tauri/import-core/tests/wide.rs), [описание формата](DAILY_WIDE_REPORTS.md) |
| Удаление отчётов | Сверить выбранные ID, календарь и аналитику после перезапуска. В общей папке проверить на двух независимых клиентах актуальное поколение и личную базу второго клиента. Сохранённые снимки рассматриваются отдельно. У широкого Excel отдельно проверить доступность общих замечаний для оставшихся дней. | [`unified_data_admin.rs`](../tauri/src-tauri/src/unified_data_admin.rs), [`shared_runtime_tests.rs`](../tauri/src-tauri/src/shared_runtime_tests.rs), [`windows_smoke.py`](../tauri/tests/windows_smoke.py), [`windows_shared_smoke.py`](../tauri/tests/windows_shared_smoke.py) |

Из корня репозитория:

```sh
node --test tauri/tests/*.test.cjs tests/test_*.cjs
npm --prefix tauri run prepare:frontend
cargo test --locked --manifest-path tauri/import-core/Cargo.toml
cargo test --locked --manifest-path tauri/storage-core/Cargo.toml
```

Для приёмки Windows используйте [Tauri Windows CI](../.github/workflows/tauri-windows.yml). По ссылке на запуск сверяйте SHA и итог `success`. Для интерфейса смотрите шаг `Run installed Windows application with real WebView2`, для общей папки также шаг с установленными клиентами и Windows SMB.

## Сверка рабочего Excel

Синтетические тесты проверяют правила импорта. Приёмка конкретного формата требует рабочего образца либо обезличенного образца с сохранённой структурой листов и эталонными итогами. Для новой сверки зафиксируйте:

| Что требуется | Какие сведения зафиксировать |
| --- | --- |
| Выбор листов и структура | Формат импорта, выбранные листы, диапазон заголовков, столбцы работ, количества, суммы и контрольных итогов. Для последовательных пар укажите год и квартал каждого листа. |
| Даты | Подтверждённый тип источника и ожидаемые даты начала и конца каждого набора. Укажите адреса ячеек, содержащих дату, либо ручную привязку. Для спорного заголовка запишите исходное значение и ожидаемое решение. |
| Единицы | Подтверждённые единицы количества и валюта суммы по сопоставляемым строкам, если они применимы. При отсутствии сведений оставляйте единицу или валюту неизвестной. |
| Контрольные значения | Ожидаемое число отчётов и строк, количество и сумма по выбранным дням и подразделениям. Включите примеры пустой суммы с числовым количеством, явного нуля, пропущенного дня и ошибки. |
| Результат | Версия, SHA, настройки импорта, ожидаемое и фактическое значение с координатами ячеек, ссылки на PR и проверку. |

Сначала сравните предпросмотр с эталоном. Затем в изолированной базе сравните сохранённые отчёты, контроль качества, аналитику и CSV на тех же датах, подразделениях и работах. При разборе расхождения сохраните в задаче только обезличенный пример и результат. Рабочие книги, базы, резервные копии и журналы с личными данными храните вне репозитория.
