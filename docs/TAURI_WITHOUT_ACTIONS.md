# Сборка Windows Tauri без GitHub Actions

GitHub Actions не является обязательной частью приложения. Windows x64 NSIS-установщик можно собрать на Windows существующей командой `npm --prefix tauri run build:windows` либо кросс-компиляцией из Linux.

## Linux → Windows x64

Нужны средства **только на машине сборки**, не на компьютере пользователя:

- Rust с целью `x86_64-pc-windows-msvc`;
- `cargo-xwin`, Microsoft CRT/Windows SDK (с их условиями лицензирования);
- LLVM: `clang-cl`, `lld-link`, `llvm-lib`, `llvm-rc`;
- NSIS с плагинами и языковыми файлами;
- Node и существующий Tauri CLI из `tauri/package.json`.

Версии приложения должны совпадать в `tauri/package.json`, `tauri/src-tauri/Cargo.toml`, `tauri/src-tauri/tauri.conf.json`.

```sh
rustup target add x86_64-pc-windows-msvc
npm install --prefix tauri --no-audit --no-fund
npm --prefix tauri run prepare:frontend
npm --prefix tauri run icons
export XWIN_CROSS_COMPILER=clang
export XWIN_MSVC_SYSROOT_DOWNLOAD_URL=https://github.com/trcrsired/windows-msvc-sysroot/releases/download/2026-11-06/windows-msvc-sysroot.tar.xz
cargo xwin cache windows-msvc-sysroot
cd tauri
npx tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --ci
```

Команду подготовки кеша нужно **дождаться до завершения**, затем запускать сборку. Нельзя одновременно подготавливать и использовать один незавершённый кеш. Вариант `clang` использует поддерживаемый `cargo-xwin` готовый MSVC sysroot вместо распаковки отдельных MSI/CAB; ссылка выше фиксирует использованный выпуск.

Если инструменты распакованы в пользовательский каталог, их пути должны быть в `PATH`; для NSIS указывается `NSISDIR`. `CARGO_HOME`, `RUSTUP_HOME`, `XWIN_CACHE_DIR`, `XDG_CACHE_HOME` и кеш npm можно направить в отдельный рабочий каталог. Системные папки и `HOME` менять не требуется.

В этой среде для заголовка `Windows.h` добавлен регистрозависимый симлинк на `windows.h` внутри кеша SDK, без правки SQLite. Для распакованного NSIS использована обёртка `makensis`, которая восстанавливает `NSISDIR` перед вызовом настоящего компилятора: Tauri удаляет эту переменную из окружения дочернего процесса. При обычной системной установке NSIS такая обёртка не нужна.

Установщик появится внутри `tauri/src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`. Само приложение — `release/analiz-rabot-tauri.exe`.

## Ключ обновлений и публикация

Для сохранения проверки обновлений во время компиляции задаётся **существующий открытый ключ** в `ANALIZ_UPDATER_PUBLIC_KEY`; тот же ключ передаётся через временный `--config` в `plugins.updater.pubkey`. Ключ и адрес канала не заменяются новыми. Закрытый ключ для компиляции не нужен.

Без закрытого ключа можно получить обычный установщик для **ручной установки**, но нельзя создать действительную подпись `.sig` для обновления через Tauri Updater. Нельзя подставлять подпись прежнего EXE или публиковать такой файл в подписанный канал. Публикация остаётся отдельным действием после разрешения владельца.

Исходный автономный `index.html`, расчёты, импорт и SQLite не требуют изменения. Electron не используется.

## Границы проверки

Успешная кросс-компиляция и проверка PE/ресурсов установщика не являются проверкой запуска в Windows. Linux-тесты модуля SQLite не проверяют WebView2 и нативные диалоги. Для нового установщика нужна отдельная проверка Windows 10/11: запуск, существующая база, импорт Excel, календарь и сохранение после перезапуска.
