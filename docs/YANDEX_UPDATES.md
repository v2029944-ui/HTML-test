# Резервный канал обновлений HTML-test — Yandex Object Storage

Бакет: **html-test-updates-23727**. Подготовка выполняется отдельно от публикации релиза.
Главный источник остаётся GitHub Releases; резервный — Yandex Object Storage.
**Этот документ не означает, что файлы уже загружены и резервный канал работает.**

## Подготовка первого выпуска (0.1.2)

1. В [Object Storage](https://console.yandex.cloud/) откройте бакет `html-test-updates-23727`.
   Для **чтения объектов** установите «Для всех». Список объектов и изменение настроек оставьте закрытыми.
2. С [опубликованного выпуска Tauri 0.1.2](https://github.com/v2029944-ui/HTML-test/releases/tag/tauri-v0.1.2) скачайте два **оригинальных** файла:
   - `Analiz-rabot-Tauri-Windows-x64-setup.exe`
   - `Analiz-rabot-Tauri-Windows-x64-setup.exe.sig`
   Не перепаковывайте EXE и не генерируйте новую подпись.
3. В бакете создайте папку `tauri-v0.1.2/` и загрузите туда оба файла.
4. На компьютере, где доступен Node.js, из корня репозитория выполните (путь к .sig замените на фактический):

   ```powershell
   node tauri/backup-manifest.cjs 0.1.2 "C:\Downloads\Analiz-rabot-Tauri-Windows-x64-setup.exe.sig" "C:\Downloads\tauri-latest.json"
   ```

   Скрипт читает подпись из оригинального `.sig` и указывает адрес **Яндекса**, а не GitHub.
5. Загрузите `tauri-latest.json` **в корень бакета** после того, как EXE и .sig появились по публичным HTTPS-адресам.
6. Без авторизации проверьте в браузере:
   - https://storage.yandexcloud.net/html-test-updates-23727/tauri-latest.json
   - https://storage.yandexcloud.net/html-test-updates-23727/tauri-v0.1.2/Analiz-rabot-Tauri-Windows-x64-setup.exe

   В манифесте `version` должен быть `0.1.2`, `platforms.windows-x86_64.url` — HTTPS-адрес
   Яндекса, `signature` — содержимое соответствующего `.sig`.
   Рекомендуется сравнить SHA-256 бинарника на GitHub и Яндексе.

## Что меняется в Tauri

- Основная проверка выполняется через существующий GitHub Updater.
- Если GitHub недоступен или проверка прервана сетевой ошибкой, нативная Rust-команда
  проверяет тот же формат манифеста на Яндексе.
- Если GitHub нашёл обновление, но EXE не удалось скачать из-за сетевой ошибки,
  Яндекс может отдать **ту же самую версию**; переход на другую версию без нового
  согласия запрещён.
- Обе ветки используют **существующий публичный ключ проверки подписи** Tauri.
  Программа не принимает непроверенный EXE и не использует незащищённый HTTP.
- Ошибки подписи и несетевые ошибки установки **не** переключают источник.

Механизм требует **новой подписанной сборки Tauri**, содержащей эти изменения.
Уже установленная 0.1.2 не получает резервный адрес сама; при недоступном GitHub
переход на такую версию придётся выполнить вручную.

## Следующие выпуски

При выпуске новой подписанной версии с тем же публичным ключом повторите шаги:
выложите `tauri-v<версия>/setup.exe` и `.sig`, проверьте их, затем обновите
корневой `tauri-latest.json` (версия и подпись соответствуют **тем же байтам EXE**).
Не обновляйте манифест раньше файлов. В GitHub канал `tauri-updates` публикуется
самостоятельно, как прежде; резервный бакет не меняет его автоматически.

Секретные ключи, пароли и токены Яндекса в репозиторий не помещайте.
Ветку с этими изменениями не публикуйте как рабочую версию, пока не выполнены
локальные Node/Rust тесты, проверка скачивания из Яндекса и Windows/WebView2 тест.
Новый GitHub Actions запускать для подготовки файлов не требуется.
