# D4e — постраничная расшифровка SQL-аналитики по группам и работам

Tauri-режим дополнен таблицей «Группы и отдельные работы». После расчёта в D4d она запрашивает **50 записей** из уже существующей D2 SQL-модели, не загружая отчёты в браузер. Работает для общих итогов по выбранным подразделениям или для одного конкретного подразделения из `orgNames`.

- Новый read-only IPC `native_analysis_range_page` принимает ревизию, тип и диапазон периодов, от 1 до 100 подразделений, отдельный необязательный `organization`, строковый курсор `after` и размер 1–50. Он выполняет `analysis_range_page` через D2, в собственном потоке `spawn_blocking`, с временным SQL-фильтром; фильтр удаляется при успехе или ошибке.
- Таблица показывает `name`, `kind` (группа/работа), `count`, `amount`, `average`, признак активности. При неполном наборе периодов D2 отдаёт `null`, и интерфейс показывает «—» вместо неверного 0. Порядок — по SQL-ключу, кнопки «Далее» и «Назад» используют курсоры и не сохраняют старые страницы.
- При новом расчёте, переиндексации, смене периода, даты, подразделения или перезагрузке базы старые строки и курсоры сбрасываются. Поля даты заблокированы на время активного запроса.
- Node-тесты покрывают 50+1 записей, курсоры, потерю ревизии через backend и отсутствие ложных нулей. Windows WebView2 smoke проверяет реальный SQL-запрос пустых недельных работ после загрузки 366 тестовых дневных отчётов.
- **Это не полноценный экспорт** и не стандартный старт Tauri. `main`, самостоятельный HTML, выпускаемые EXE и пользовательские SQLite не меняются. Требуется успешный Windows CI и дальнейшая проверка корректности группировки на реальных базах перед включением в основную навигацию.
