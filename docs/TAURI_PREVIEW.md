# Выпадающие списки и уведомления Tauri — 0.1.3-beta.1

Это тестовая сборка из ветки `work/tauri-dropdown-updates-20261117`. Выпуск и канал `tauri-updates` не публикуются и не изменяются. Ветка не объединяется с `main` без отдельного разрешения. Electron не собирается; новых Electron API нет.

## Интерфейс

Нативные `select` сохраняют идентификаторы, опции, обработчики `change`, клавиатурный ввод и доступность. Их поля и списки множественного выбора используют общие цвета, границы, высоты, скругления, стрелки и состояния выбора. В WebView2/Chromium с поддержкой `appearance: base-select` браузер также оформляет раскрытые опции общими переменными темы. В старых движках работает нативный fallback: системное окно списка может отличаться в деталях оформления. Никакая библиотека селектов не добавлена.

## Обновления

Используется существующий Tauri Updater, тот же URL канала и существующий открытый ключ проверки. После загрузки данных проверка запускается автоматически, но скачивание и установка — только после подтверждения. В HTML-браузерной версии Tauri-уведомлений нет.

Уведомление содержит «Что нового», «Позже» и «Обновить». Описание из манифеста выводится обычным текстом, без исполнения HTML. Если описания нет, это явно указано. «Позже» сохраняет номер версии в отдельном локальном предпочтении `work-reports-update-deferred-v1`; следующая версия уведомит снова. Индикатор в «Управлении» остаётся видимым, а ручная проверка вновь показывает уведомление. Недоступность предпочтений не блокирует приложение и не создаёт ложного сообщения об успешном сохранении отсрочки.

Во время чтения/ручной проверки Excel и незавершённых записей данных установка запрещена. Tauri bridge считает незавершённые записи SQLite и правил и чтения Excel; счётчики освобождаются также при ошибке. На время подтверждения и установки новая запись/импорт запрещены; занятость повторно проверяется после ответа на подтверждение. При ошибке подписи/сети интерфейс разблокируется. Проверку подписи выполняет Tauri Updater; отключения проверки нет.

Схема SQLite, финансовые расчёты, правила разбора Excel, данные и формат резервных копий не менялись.

## Проверки

Локально:

```
node --test tauri/tests/*.test.cjs tests/*.cjs desktop/core.test.cjs
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -v
```

Полный Node-набор включает существующие проверки общих компонентов; это не сборка или разработка Electron. Rust/Windows проверяются существующим Tauri workflow в выделенной тестовой ветке. Его подписанная сборка вызывает `build:signed:windows`, но **не вызывает `publish.cjs`**. Ключи не включаются в исходники или артефакты.

`tauri/tests/windows_smoke.py` запускается только в изолированном Windows CI: устанавливает EXE в временную папку, запускает настоящий WebView2, подключает Playwright через локальный отладочный порт, импортирует синтетический годовой XLSX, проверяет SQLite, клавиатуру списков, високосный февраль и повторный запуск. При непустой базе проверка останавливается без замены данных. Отладочный порт включается только переменной окружения дочернего процесса теста; в обычном запуске приложения его нет.

Артефакт `Tauri-Windows-preview` содержит `setup.exe`, `setup.exe.sig`, `build-info.json` и, при успешном запуске WebView2, снимок окна. `build-info.json` фиксирует размер, SHA256, движок и реально пройденные проверки. Наличие установщика само по себе не подтверждает успешный Windows-запуск: нужно проверить результат шага smoke и содержимое отчёта. Второй артефакт существующего workflow содержит исходный NSIS-установщик.

Сборка требует Node/Rust только от CI. Пользователь скачивает готовый EXE; средства разработки ему не нужны. Физический Windows 10/11, личные Excel и установка подписанного онлайн-обновления на пользовательском компьютере требуют отдельной проверки. CI не публикует этот тестовый установщик в рабочий канал.
