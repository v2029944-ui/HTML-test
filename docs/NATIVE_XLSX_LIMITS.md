# Повышенные лимиты потокового XLSX-импорта Tauri (подготовка)

Это изменение **только для нативного Rust-импорта** и относится к исходному коду в PR; опубликованный установщик 0.1.5 имеет старые пределы. Автономный `index.html` и классический браузерный путь Tauri не затрагиваются.

| Параметр | До | В новом нативном профиле |
|---|---:|---:|
| ZIP/XLSX на диске | 30 МиБ | **100 МиБ** |
| Один распакованный XML-компонент | 48 МиБ | **128 МиБ** |
| Совокупный объём распакованной книги | 192 МиБ | **768 МиБ** |
| Ячеек во всех листах | 3 000 000 | **15 000 000** |
| Координата строки листа | 60 000 | **100 000** |
| Объём приватной временной SQLite | 2 ГиБ | **4 ГиБ** |
| Столбцы листа | 2048 | 2048 |
| Коэффициент распаковки ZIP | 1000 | 1000 |
| XML-токен / текст ячейки | 1 МиБ / 65 536 байт | без изменения |

**Разделение интерфейсов.** У классического импорта осталось 30 МиБ на XLSX, 1 500 000 учитываемых ячеек и ограничения браузерного XML DOM. Базовый API чтения Excel целиком в JavaScript не повышался. В списке папки `tooLarge` показывает прежний лимит классического интерфейса, а `nativeTooLarge` — новый 100-МиБ предел SQL-редактора правил. Нативный импорт по отдельному абсолютному пути использует профиль `Limits::default()`.

**Ограничения остаются обязательными.** Парсер по-прежнему сверяет CRC/размеры ZIP, запрещает ZIP64 и подозрительные пути, ограничивает коэффициент распаковки, токены, координаты, суммарные ячейки, использует SQLite на диске, проверяет хеш источника и отменяет импорт без частично записанного отчёта. При нехватке диска или превышении любого порога операция должна завершаться ошибкой, не изменяя живую базу. Превышение 100 МиБ файла может наступить позже, чем бюджет XML/ячеек.

**Проверки:** модульные Rust-тесты утверждают параметры профиля, границы строк, отклонение размера архива и превышения ячеек. Node-тест проверяет, что XLSX 40 МиБ можно выбирать для нативного правила при сохранении старого флага классического читателя. Полный Windows CI и импорт реальных больших производственных XLSX пока не подтверждены; нельзя утверждать, что полный цикл для 15 млн ячеек гарантированно проходит. Отдельные измерения `docs/NATIVE_IMPORT_PROGRESS.md` касаются прежнего профиля и не доказывают безопасность нового.

**Ограничение по диску:** временная SQLite теперь может потребовать до 4 ГиБ, помимо исходного XLSX, рабочей базы и возможной резервной копии. Перед использованием больших книг разумно иметь не менее 8–10 ГиБ свободного места; это практический ориентир, а не автоматическая проверка диска. Срабатывание любого меньшего ограничения (например, XML-компонента, суммарной распаковки или числа строк на листе) может отклонить книгу до достижения 15 млн ячеек.

**Перед релизом** нужны end-to-end испытания 3–15 млн ячеек для простого и широкого формата: парсинг, предпросмотр, подтверждение конфликтов, backup, commit в тестовую SQLite, контроль итогов, запуск GUI на Windows, нехватка свободного места и корректное завершение. Не используйте рабочую базу для таких испытаний. Данные в пользовательской SQLite никогда не перезаписываются только по факту появления файла в папке.
