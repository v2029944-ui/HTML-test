# HTML-test — автономная аналитика отчётов

Тестовая версия Tauri 0.1.3-beta.1: [результаты успешной Windows GUI-проверки](docs/TAURI_PREVIEW.md). Подписанный рабочий выпуск остаётся 0.1.2.

## Windows-приложение: Tauri 2 + SQLite

Основная настольная версия — **Tauri 2** с локальной базой **SQLite**. [Подписанный установщик Tauri 0.1.2 для Windows x64](https://github.com/v2029944-ui/HTML-test/releases/download/tauri-v0.1.2/Analiz-rabot-Tauri-Windows-x64-setup.exe). Новые сборки смотрите в [GitHub Releases](https://github.com/v2029944-ui/HTML-test/releases). Изменения в исходном коде не появляются в ранее опубликованном EXE автоматически.

Tauri использует исходный HTML-интерфейс, отслеживает выбранную папку Excel и сохраняет отчёты в SQLite (системные «Документы / Анализ работ / reports.sqlite3»). Приложение работает локально, интернет нужен только для проверки и загрузки обновлений.

Сборка, миграция и онлайн-обновления: [tauri/README.md](tauri/README.md). Модуль импорта папки Excel — `tauri/folder-importer.js`. Новые настольные функции разрабатываются только для Tauri.

## Самостоятельный HTML

Файл [index.html](index.html) сохранён для работы в браузере без установки и сети. Там используется IndexedDB, а не SQLite; автоматическое отслеживание папки доступно в Tauri. Сервер и Node.js для запуска HTML не нужны.

## Навигация

Основные вкладки — **«Аналитика»** и **«Анализ изменений»**. Меню **«Управление»** справа объединяет **«Отчёты»** (Excel, календарь и качество данных), **«Группы работ»** и **«Настройки»**. Кнопка **«Обновить отчёты»** в шапке открывает раздел отчётов; проверка и сохранение файлов выполняются существующими средствами этого раздела.

На первом запуске открывается аналитика. Затем приложение возвращается к последнему выбранному разделу: его идентификатор хранится отдельно в локальных предпочтениях (`work-reports-view-v1`), без изменения отчётов, групп и формата резервных копий. При недоступности предпочтений открывается аналитика. На телефоне остаются две основные вкладки и компактное меню «Ещё» («Управление»); меню закрывается после выбора, по Escape или нажатию вне его.

Локальные проверки: `node --test tests/*.cjs tauri/tests/*.test.cjs` и `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -v`. Браузерным тестам требуются установленные Playwright и Chromium; приложению они не нужны.

## Импорт Excel

1. Откройте «Управление» → «Отчёты», нажмите **«Выберите файл»**, укажите `.xlsx`, выберите тип, дату начала и лист.
2. Для привычной структуры с горизонтальными тройками «Работа / Количество / Сумма» оставьте автоматическое распознавание. Нажмите «Проверить Excel» перед сохранением.
3. Для нестандартных листов откройте **«Столбцы и даты каждого набора»** → **«Указать столбцы вручную»**. Для каждого набора введите буквы столбцов работы, количества и суммы и номер строки заголовка. Столбцы не обязаны быть соседними. «Добавить набор столбцов» создаёт ещё один отчётный блок.
4. В том же разделе можно изменить дату каждого найденного набора отдельно. Без изменений даты считаются последовательными от первой недели или месяца. Пересекающиеся даты внутри импорта отклоняются.
5. Сверьте предпросмотр, замечания и контрольные суммы. Не исправляйте расхождения подгонкой чисел в приложении.

Ограничение: встроенный XLSX-парсер поддерживает известные структуры ZIP/XML, а не все возможности Excel. Ручной маппинг помогает с расположением колонок, но не заменяет диагностику формул и неподдерживаемых форматов.

## Контроль качества

В «Контроле качества данных» показываются строка и известный адрес ячейки Excel, например `Лист1!B27`. Для новых импортов доступно раскрываемое «Как проверить и исправить» и копирование адреса. Для расхождений итога адрес относится к **контрольной ячейке** — сама ошибка может находиться среди работ выше. Ранее сохранённые отчёты без координат не получают вымышленных адресов.

## Сравнение подразделений в графиках

Откройте **«Аналитика → Подробный анализ → Графики и сравнение подразделений»**. В поле **«Сравнивать»** выберите **«Подразделения»**. Линейный график, столбцы и таблица отображают выбранные подразделения по общему диапазону недель или месяцев. Подразделения выбираются в основном фильтре, а показатели для этого графика — в отдельном поле ниже. В других аналитических разделах сохраняется основной выбор показателей.

В поле **«Показатели этого графика»** можно выбрать сумму, количество и среднюю сумму на работу (в любом сочетании). Каждая комбинация подразделения и показателя — отдельная серия: два подразделения × три показателя = шесть линий или столбцов. По умолчанию выбраны все три показателя. В поле **«Как расположить показатели»** можно выбрать «Вместе — относительная шкала (%)» или «Отдельно — исходные значения». Показатели для этих графиков выбираются **отдельно** от верхнего фильтра «Показатели»; подразделения остаются общими для всей аналитики.

**Как читать совместный линейный график:** цвет обозначает подразделение; **сплошная линия — сумма, штриховая — количество, точечная — средняя сумма на работу**. Тип линии всегда привязан к показателю и не зависит от порядка выбора. Легенда под графиком показывает **реальный цвет и рисунок** каждой серии. Для столбцов цвет обозначает подразделение, а насыщенность — показатель; образцы столбцов показаны в легенде.

**Шкала совместного графика:** величины с разными единицами показываются в процентах от максимального по модулю значения **своего показателя** за выбранный диапазон. Это не процент роста. Точные числа доступны в подсказках и таблице. Отрицательные значения расположены ниже нуля, отсутствие данных не заменяется нулём. Если выбран один показатель или раздельные графики, используется его исходная шкала.

Поле **«Какие работы учитывать»** задаёт расчёт: **все выполненные работы** (по умолчанию) либо **только отмеченные работы и группы**. Под графиками отображается таблица общих итогов и количества полных отчётных периодов каждого подразделения. Если отчёт подразделения отсутствует хотя бы в одном периоде диапазона, его итог за диапазон обозначается прочерком; на графике пропущенная точка не считается нулём.

Прежний режим «Работы и группы» остался доступен в том же переключателе. Для отдельного табличного сравнения относительно базового подразделения можно использовать соседний раздел **«Сравнение»**.

## Календарь и загруженные отчёты

На вкладке «Импорт Excel» расположена сетка из 12 недель либо 12 месяцев с кнопками «Раньше/Позже». Отмечаются загруженные, неполные, проблемные и отсутствующие периоды. При выборе периода можно просмотреть источник и перейти к проверке качества. Отсутствующий отчёт никогда не превращается в нулевой показатель.

## Сводка для печати

В разделе «Аналитика → Итоги за период» нажмите **«Печать сводки / PDF»**. Формируется отдельный печатный лист с итогами, результатами подразделений, сравнением с предыдущим равным интервалом и крупнейшими изменениями. В открывшемся диалоге браузера выберите принтер или «Сохранить как PDF». Неполные данные и замечания источника обозначаются отдельно. Дополнительные библиотеки для экспорта не используются.

## Локальное хранение и резервные копии

Отчёты сохраняются в IndexedDB браузера, при недоступности — в ограниченном localStorage. Если запись отклонена браузером или переполнено хранилище, приложение выводит ошибку; прежний набор отчётов не подменяется ложным успешным сохранением. Восстановление полной копии, переименование подразделений и импорт отчётов вместе со справочником выполняются одной транзакцией. Устройство и браузер **не синхронизируются автоматически**. Регулярно скачивайте полную JSON-копию в «Данные и настройки».

## Ограничения и проверка

- Рабочая программа остаётся одним `index.html` и не требует внешних зависимостей.
- Ручная группировка услуг сохраняется; автоматической группировки нет.
- История импортов и сохранённые наборы фильтров не добавлялись.
- Локально изолированно проверены функции Excel-мэппинга, непоследовательные даты, отбрасывание пересечений, адреса ячеек, календарные статусы, печатная сводка и успешные/неуспешные транзакции.
- Перед рабочим применением нужно отдельно проверить полный импорт реального Excel, сохранение после закрытия браузера, печать и экранные размеры 320–1440 px. Физический iPhone/Safari и запуск через `file://` не были проверены автоматическим браузерным тестом.

## Уточнения графиков и подписей — 14.11.2026

- Цвет подразделения одинаков в совместном и раздельном графике, сравнении итогов и динамике. Цвет работы или группы стабилен по её ключу и не зависит от порядка выбора; используется конечная палитра темы, поэтому у разных услуг цвета могут повторяться.
- Неполный период подписан «Неполные данные: N из M подразделений». Общий итог не строится; частичная сумма не выдаётся за полную. Числовой рост и снижение выделены нейтрально, направление остаётся в тексте и знаках. Цвета ошибок и проверки совпадения итогов сохранены.
- При выборе более восьми серий над графиком виден счётчик и список диапазонов серий (1–8, 9–16 и т. д.). Этот выбор меняет только видимые серии конкретного графика; состав выбранных работ и данные таблиц не меняются. Легенда раскрывается по высоте без внутренней прокрутки.
- Общие фильтры и локальные показатели обзора, графика, сравнения, отклонений и изменений подписаны отдельно. Формула средней суммы дополнена предупреждением: единицы количества работ должны быть сопоставимы.
- Календарь показывает одновременно неполноту и число замечаний. Одинаковые сообщения из warnings и issues считаются один раз; число в подробностях рассчитывается так же.

Проверено локально: `python -m unittest discover -s tests -v` — 5 браузерных тестов Chromium; `node --test tests/test_department_metrics.cjs` — существующие проверки совместных графиков; синтаксис обоих встроенных скриптов. Новые сценарии проверяют постоянство цветов при смене состава и порядка подразделений, линии/столбцы, частичный отчёт, календарь с дублирующимся сообщением, нейтральную индикацию и выбор серий на 320/390/1024/1440 px в светлой и тёмной темах. Просмотрены скриншоты графика на 320 и 1280 px. Существующий CSV-тест приведён к независимому выбору показателей графика и актуальным единицам экспорта; исходное падение воспроизведено до правок приложения.

Расчётные функции, импорт Excel, формат хранения и пользовательские данные не менялись. В этом проходе реальный Excel и физический iPhone/Safari не проверялись. GitHub Actions не добавлялись и не запускались.

## Дополнительная проверка графиков — 14.11.2026

- Название работы и её внутренний ключ `work:<название>` получают один и тот же цвет. Название группы и ключ `group:<id>` также сопоставляются; цвет группы сохраняется при переименовании с тем же идентификатором.
- На обычных линейных графиках отсутствующие между соседними датами недели или месяцы показываются словом «Пропуск» и пояснением дат. Линия не соединяет точки через отсутствующие периоды. Количество, суммы и пропущенные данные при этом не подменяются нулевыми значениями.
- Дополнены регрессионные проверки непрерывных и разорванных линий, пропущенного месяца и одинакового цвета работ/групп в разных разделах. Формат локальных данных, расчёты и импорт Excel не изменены.

## Цвета изменений и качества данных — 14.11.2026

- **Синий** — числовое увеличение (в том числе «Необычно выше»), **фиолетовый** — уменьшение («Необычно ниже»). Это не оценка эффективности. В таблицах изменений подсвечены сами разницы, процент и направление; в сводках — изменение от базы. Без изменений и при отсутствии сопоставимых данных цвет не назначается.
- **Зелёный** — состояние проверки без зафиксированных проблем или полный отчёт; **красный** — зафиксированные ошибки/неполнота, где качество действительно хуже. Замечания, требующие проверки, остаются предупреждениями. Палитры дневной и ночной темы поддерживают различимость.
- Отдельные текстовые пояснения к цветам добавлены в обзор, отклонения от среднего и анализ изменений; цвет не служит единственным обозначением — направление и статус остаются в тексте.

## Группы, поиск и выбор страницы — 16.11.2026

«Группы работ» — единый раздел со списком групп, кнопкой «Создать группу», раскрываемым редактором, проверкой справочника и загрузкой справочника услуг. Нажатие «Изменить группу» открывает редактор и заполняет текущий состав. Импорт/экспорт групп JSON остаётся в этом разделе; группы общие для всех подразделений и редактируются вручную. Остальные настройки не объединялись: оформление, названия подразделений, резервная копия и очистка выполняют разные задачи.

В каждом постраничном списке есть выбор «Страница»: контроль качества, вклад работ, отклонения от среднего, частота работ, проверка групп, анализ изменений и выбор работ редактора. Можно сразу перейти к нужному номеру, сохранив кнопки соседних страниц. В редакторе вместо ограничения первыми 250 названиями доступны все страницы по 25 работ. Отметки сохраняются при переходах и поиске; установка чекбокса не перестраивает строку прямо под указателем. Поиск находит и отмеченные работы из старой копии группы, которых уже нет в текущих отчётах и справочнике. На телефоне кнопки навигации занимают отдельную строку.

Единое правило поиска применяется к названиям работ и групп в пяти существующих полях:

- При любой длине запроса: сначала совпадения в начале названия по алфавиту, затем совпадения внутри, также по алфавиту. Началом считается начало полного названия.
- Регистр не учитывается, лишние пробелы обрабатываются существующей нормализацией. При пустом запросе сохраняется прежний порядок списка.
- Проверка справочника для длинного запроса дополнительно учитывает связанную группу или состав группы, как и раньше.
- Результаты активного поиска в «Анализе изменений» собраны в один список с заданным порядком; отдельные таблицы показателей сохранены, признаки малой базы остаются в строках. Другая сортировка снова доступна после очистки поиска.

Локально прошли `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -v` (10 браузерных тестов Chromium), `node --test tests/test_department_metrics.cjs` (включая новые проверки поиска) и проверка синтаксиса обоих встроенных скриптов. Синтетический каталог из 304 названий проверяет дальние страницы всех семи списков, сброс страницы при поиске, короткий/длинный запрос, сохранение отметок, создание/изменение общей группы, ручной перенос, JSON-экспорт/импорт и перезагрузку. Исходные отчёты при работе с группами не меняются. Проверены размеры 320/390/1024 px и светлая/тёмная тема; просмотрены скриншоты группы на 320 и 1280 px. Прежние регрессии аналитики, CSV, календаря и импорта даты также проходят.

## Охват группами и сравнение диапазонов — 16.11.2026

В разделе групп показано «Названий в группах: N из M» и число названий без группы. В каждой группе — её число уникальных названий из общего количества. Общее количество — объединение уникальных названий из всех отчётов, справочника и сохранённых групп, независимо от выбранных подразделений, периода и поискового фильтра. Это число названий, а не выполнений работ. Поиск «Найти группу» использует общую сортировку: совпадения в начале названия первыми, затем внутри. Показано также число найденных групп.

В фильтре «Работы и группы» и списках назначения группы используется метка `▦ … (группа)`. В обычных названиях услуг её нет. Метка добавляется только при отображении: имена, идентификаторы, выбранные категории и JSON не изменены.

В «Сравнение периодов и подразделений → Периоды» добавлен выбор «Два отдельных периода / Два диапазона». Для каждого диапазона отдельно задаются начало и конец включительно. Так можно сравнить три недели с тремя другими неделями или несколько месяцев с другим диапазоном. Даты общие для выбранных подразделений; сравнение отдельных периодов сохранено. Таблица, карточки, CSV и вклады услуг используют одни и те же границы через существующий `aggregateReportRange`.

Каждый диапазон суммируется отдельно, с исключением конфликтующих исходных отчётов существующим индексом. Пропущенный отчёт не заменяется нулём; общий итог при неполноте недоступен, указано подразделение и недостающая дата. При разной длительности интервалов выводится предупреждение: сравниваются суммы, без автоматического пересчёта на неделю. Если интервалы пересекаются, это явно обозначено: общий отчёт входит по одному разу в каждый итог. Средняя сумма остаётся общей суммой, делённой на общее количество. Границы выбираются из загруженных периодов; пропуски внутри диапазона проверяются расчётом полноты.

На 320/390/1024 px проверены отсутствие переполнения и высота новых полей не менее 44 px.
- `node --test tests/test_department_metrics.cjs` — проверки уникальных названий, диапазонов по три недели и три месяца, дробного количества, взвешенного среднего, групп без двойного подсчёта, нулевой базы, пропусков, повторных и пересекающихся отчётов.

## Дневные отчёты и расположение фильтров — 16.11.2026

Выбор «Что сравниваем» перенесён под заголовок раздела сравнения. Общий период подразделений расположен под выбором временного интервала; подписи находятся над соответствующими полями. Поля дат имеют одинаковый размер и на телефоне располагаются друг под другом. Аналогично перенесён выбор типа периода в календаре отчётов.

Добавлен тип периода «Дни». Для импорта выберите его и задайте «Первый день»: каждый следующий горизонтальный набор колонок существующего Excel-формата относится к следующему календарному дню. Дату каждого набора можно изменить вручную; повторные и пересекающиеся даты блокируют сохранение. Ошибки асинхронной проверки файла теперь выводятся в интерфейсе. Формат исходного Excel не изменён.

Дневные отчёты поддерживаются в аналитике, сравнении отдельных дней и диапазонов, анализе изменений, отклонениях от среднего, регулярности услуг, календаре, контроле качества, CSV и резервных копиях. Для просмотра выбирайте «Дни» в соответствующем фильтре. Среднее за 4/8 дней использует фактически доступные отчёты и показывает полноту данных. Пропуски, включая выходные без отчёта, не считаются нулём. Недельные и месячные отчёты не разбиваются автоматически на дни и не смешиваются с дневными итогами.

Существующие недельные и месячные данные совместимы. Версии JSON резервной копии и IndexedDB остаются равны 1; для восстановления копии с дневными отчётами нужна обновлённая версия приложения. Группы остаются общими и ручными.
