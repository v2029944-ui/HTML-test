В 1.12.12 справочник показывает по 50 названий работ на странице и позволяет назначать группу сразу нескольким работам. При импорте Excel видна база назначения, а сводка показывает до пяти работ с наибольшим ростом и снижением. [Подключение сотрудников](tauri/README.md#общая-база-сотрудников)

«Анализ работ» — настольное приложение Tauri 2 для анализа Excel-отчётов о работах. Данные хранятся в личной SQLite или в общей базе сотрудников через сетевую папку.

[Все выпуски](https://github.com/v2029944-ui/HTML-test/releases) · [Подключение общей базы](tauri/README.md#общая-база-сотрудников).

## Интерфейс

Основные разделы — **«Сводка»** и **«Анализ изменений»**. В меню **«Управление»** находятся **«Отчёты»**, **«Группы работ»**, **«Базы данных»** и **«Настройки»**. На узких экранах используется компактное меню.

- Аналитика: итоги, графики, сравнение подразделений и периодов, динамика работ, структура и частота услуг, отклонения от обычных значений.
- Анализ изменений: поиск, направления роста и снижения, пороги, сравнение с предыдущим периодом или внутри диапазона.
- Группы работ: ручной состав групп, справочник, проверка и импорт/экспорт JSON.
- Отчёты: импорт Excel, календарь по месяцам с просмотром дней, список загруженных отчётов, контроль качества и исходные ячейки ошибок.
- Итоги за период можно распечатать или сохранить как PDF через диалог печати. Доступен экспорт некоторых таблиц в CSV; это не полноценный экспорт всей аналитики в Excel.

**Качество данных:** отсутствие отчёта не считается нулём; неполные, конфликтующие и содержащие замечания периоды выделяются отдельно. Недельные и месячные суммы не распределяются автоматически по дням.

## Импорт Excel

Настройки поддерживают четыре подразделения. Имена строк итогов в Excel должны совпадать с настроенными именами. Для переменного числа подразделений потребуется изменить контракт импорта папки и настройки SQLite, проверку передачи отчётов между базами и загрузку резервных копий в браузере. При удалении подразделения понадобится определить, как учитывать его исторические строки в фильтрах и итогах.

1. Откройте **«Управление» → «Отчёты»** и выберите файл `.xlsx`.
2. Укажите подходящий тип и структуру, если они не распознаны однозначно, а также первую дату или месяц.
3. Нажмите **«Проверить Excel»** и изучите распознанные периоды, контрольные суммы и замечания.
4. Нажмите **«Сохранить отчёты»**. Для опасной замены или сохранения с замечаниями требуется подтверждение.

Поддерживаются следующие структуры Excel:

- **Обычные отчётные периоды:** повторяющиеся группы столбцов «Работа / Количество / Сумма».
- **Дневные данные за квартал или год:** один общий столбец работ и пары «Количество / Сумма» для отдельных дней; итоговые столбцы проверяются отдельно. Подробнее — [инструкция](docs/DAILY_WIDE_REPORTS.md).
- **Дополнительные виды отчётов:** простые построчные XLSX по встроенному профилю (например, «Подразделение / Работа / Часы / Объём» или «Подразделение / Показатель / План / Факт»). Нужны выбор профиля, даты, предпросмотр и подтверждение. [Инструкция](docs/EXTENSIBLE_REPORT_KINDS.md).

Для широких дневных таблиц приложение читает даты из книги. Если в шапке идут последовательные пары без дат, явно укажите год и квартал или год целиком. Для широких книг можно выбрать несколько листов. [Инструкция](docs/DAILY_WIDE_REPORTS.md).

В Tauri можно выбрать папку Excel и задать правила для файлов. Автоимпорт включается на текущий сеанс и добавляет новые проверенные отчёты в выбранную базу, пока приложение открыто. Файлы с замечаниями, ошибками или конфликтами требуют ручной проверки. Удаление файла из папки не удаляет сохранённый отчёт. [Импорт Excel в Tauri](tauri/README.md#импорт-excel).

## Где хранятся данные

**Tauri:** SQLite по пути `Документы/Анализ работ/reports.sqlite3` в системной папке документов текущего пользователя. При первом запуске предусмотрен перенос прежних `reports.json` и `desktop-config.json` из той же папки; оригиналы не удаляются. Самостоятельная браузерная версия использует собственное хранилище и не синхронизирует его с SQLite автоматически.

**Резервные копии:** на вкладке «Управление → Базы данных» можно сохранить копию активной личной или общей базы. Для восстановления личной базы сначала проверьте файл SQLite, сравните число отчётов и подтвердите замену при следующем запуске. В этом же разделе можно включить «Ежедневная копия выбранной базы». Приложение хранит локально до семи ежедневных копий для каждой базы, где включено расписание. Копии создаются, пока приложение открыто и эта база выбрана. Снимки общей папки служат для синхронизации. [Резервные копии и общая база](tauri/README.md#общая-база-сотрудников) · [Процедура восстановления](docs/SQLITE_RECOVERY_DRILL.md).

Excel, база отчётов и настройки не отправляются на внешний сервер. Интернет используется для проверки и загрузки подписанных обновлений Tauri, если механизм настроен.

## Разработка и проверки

Сборка Tauri и Windows-проверка описаны в [tauri/README.md](tauri/README.md). Для текущих исходников предусмотрены:

```text
node --test tauri/tests/*.test.cjs tests/test_*.cjs .github/scripts/pr-safety.test.cjs
npm --prefix tauri run prepare:frontend
python -m unittest discover -s tests -p test_sqlite_restore_copy.py -v
python -m unittest discover -s tauri/tests -p 'test_reference_*.py' -v
cargo test --locked --manifest-path tauri/src-tauri/Cargo.toml
cargo test --locked --manifest-path tauri/import-core/Cargo.toml
cargo test --locked --manifest-path tauri/storage-core/Cargo.toml
```

Для Node используется Node.js 24. Шаблон `tests/test_*.cjs` выбирает тесты; файлы `native_*_golden.cjs` — вспомогательные программы, ожидающие JSON из stdin, и не предназначены для `node --test`. Подготовка интерфейса создаёт `tauri/web/`; изменять нужно исходники, а не файлы этого каталога.

Полный браузерный набор запускается отдельно командой `python -m unittest discover -s tests -v` в окружении с Playwright и Chromium; часть тестов ожидает `/usr/bin/chromium`. Тесты `test_reference_*.py` проверяют вспомогательную логику Windows GUI-проверки, а само установленное приложение проверяется в Windows с WebView2. [Локальный Windows-скрипт и границы проверок](docs/WINDOWS_RUNNER.md).

Для архитектурного ревью Rust можно запускать [deslop-please](https://github.com/deterministic-machines/deslop-please). Установите версию `0.1.4` и компоненты `rust-analyzer` и `rust-src` активного toolchain. Для проверенной конфигурации использован Rust `1.99.0`.

```sh
rustup component add rust-analyzer rust-src
rustup target add x86_64-pc-windows-msvc
cargo install deslop-please --version 0.1.4 --locked
npm --prefix tauri run prepare:frontend
(cd tauri/src-tauri && deslop-please --target x86_64-pc-windows-msvc)
(cd tauri/import-core && deslop-please)
(cd tauri/storage-core && deslop-please)
```

Команды с `cd` приведены для Bash. В PowerShell перейдите в каждый каталог отдельно и выполните соответствующую команду `deslop-please`. Линтер индексирует одну платформу и набор Cargo features за запуск. Для проверки Linux запустите его без `--target` в окружении с системными зависимостями Tauri.

Циклы зависимостей и доступ к внутреннему состоянию стоит разбирать по показанным связям. Ширина интерфейса, длина файла и число файлов в каталоге помогают выбрать участки для дальнейшего ревью. Линтер используется как дополнительная локальная проверка. Сборка и тесты выполняются отдельно.

Подписанная 1.12.12 проверена на синтетических книгах и изолированных базах. Проверки включали Windows/WebView2, импорт Excel, SQLite и обмен двух установленных клиентов через SMB. [Windows CI](https://github.com/v2029944-ui/HTML-test/actions/runs/46113829293) · [Подписанная сборка](https://github.com/v2029944-ui/HTML-test/actions/runs/46117201011).

Корневой [index.html](index.html) используется при подготовке интерфейса Tauri и сохраняет самостоятельный запуск в браузере. Основная платформа разработки — Windows Tauri; сохранение автономного HTML закреплено в [AGENTS.md](AGENTS.md).

Браузерные тесты требуют Playwright и Chromium, Rust-тесты — Rust toolchain. Windows GUI-тест работает на Windows runner и проверяет установленную тестовую сборку с WebView2.
