# Анализ работ — Tauri 0.1.3 и автономный HTML

HTML-test анализирует отчёты о выполненных работах: количество, суммы, подразделения, работы и группы, динамику и изменения по дням, неделям и месяцам. Данные Excel обрабатываются локально; отдельный сервер для аналитики не требуется.

**[Скачать «Анализ работ» 0.1.3 для Windows x64](https://github.com/v2029944-ui/HTML-test/raw/refs/heads/main/downloads/0.1.3/Analiz-rabot-0.1.3-Windows-x64-setup.exe)** — установщик 4,5 МБ, ручная установка.

Для скачивания из закрытого репозитория войдите в GitHub под аккаунтом с доступом к нему.

Страница выпуска: [Tauri 0.1.3](https://github.com/v2029944-ui/HTML-test/releases/tag/tauri-v0.1.3).

### Что изменилось

- Основные вкладки «Аналитика» и «Анализ изменений», меню «Управление» для отчётов, групп и настроек.
- Запоминание последнего открытого раздела и компактная навигация на телефоне.
- Единое оформление обычных и множественных списков, управление с клавиатуры, поддержка светлых и тёмных вариантов оформления.
- Уведомления о подписанных обновлениях: «Что нового», «Позже», «Обновить», индикатор в меню, запоминание отсрочки, прогресс и сообщения об ошибках.
- Блокировка установки обновления во время импорта Excel и записи данных.

Исходный автономный HTML, расчёты, форматы Excel, путь и схема SQLite сохранены.

Состав готового EXE зафиксирован коммитом `f26e5e6`. В исходники также добавлены [диагностика лимитов XLSX и инструмент измерений](docs/XLSX_LIMITS.md), проверенные отдельно. Для включения этой последующей правки в приложение требуется новая сборка. Подробности — [описание 0.1.3](docs/TAURI_013.md) и [сборка без Actions](docs/TAURI_WITHOUT_ACTIONS.md).

**Статус исходников (сверено с `main` 18.11.2026):** после сборки 0.1.3 в репозиторий добавлены Rust-модуль `tauri/import-core` для потоковой обработки и преобразования XLSX и дополнительные исправления определения дат. Они **не входят в готовый EXE 0.1.3**. Модуль пока не подключён к пользовательскому импорту Tauri; рабочее приложение всё ещё использует JavaScript и читает всю историю отчётов из SQLite. Подробнее: [состояние нативного импорта](docs/NATIVE_IMPORT_PROGRESS.md).

### Как установить

1. В текущей программе откройте «Управление» → «Настройки» и сохраните полную резервную копию.
2. Скачайте установщик по ссылке выше, закройте программу и запустите `Analiz-rabot-0.1.3-Windows-x64-setup.exe`.
3. После установки откройте программу, проверьте отчёты, группы и итоги за знакомый период. Данные остаются в системной папке документов: `Анализ работ/reports.sqlite3`.

**0.1.3 доступна для ручной установки; в канале онлайн-обновлений пока не опубликована:** подпись установщика для Tauri Updater не создана, версия не добавлена в канал обновлений. Механизм проверки будущих подписанных обновлений, прежний открытый ключ и адрес канала сохранены. Эта сборка устанавливается вручную.

Предыдущий опубликованный подписанный выпуск — [Tauri 0.1.2 для Windows x64](https://github.com/v2029944-ui/HTML-test/releases/download/tauri-v0.1.2/Analiz-rabot-Tauri-Windows-x64-setup.exe). Это отдельная, более ранняя версия.

**Новый установщик 0.1.3 ещё не запускался в настоящей Windows/WebView2.** Подтверждены кросс-сборка, версия и архитектура PE, содержимое установщика и локальные тесты; результаты прежней GUI-проверки беты не заменяют испытание этого EXE.

> Прежние исходники Electron остаются для совместимости; разработка версии 0.1.3 ведётся на Tauri. Их очистка подготовлена в [PR #13](https://github.com/v2029944-ui/HTML-test/pull/13). Tauri пока использует общий модуль импорта `desktop/renderer.js`.

## Интерфейс

Основные разделы — **«Аналитика»** и **«Анализ изменений»**. В меню **«Управление»** находятся **«Отчёты»**, **«Группы работ»** и **«Настройки»**. На узких экранах используется компактное меню.

- Аналитика: итоги, графики, сравнение подразделений и периодов, динамика работ, структура и частота услуг, отклонения от обычных значений.
- Анализ изменений: поиск, направления роста и снижения, пороги, сравнение с предыдущим периодом или внутри диапазона.
- Группы работ: ручной состав групп, справочник, проверка и импорт/экспорт JSON.
- Отчёты: импорт Excel, календарь по месяцам с просмотром дней, список загруженных отчётов, контроль качества и исходные ячейки ошибок.
- Итоги за период можно распечатать или сохранить как PDF через диалог печати. Доступен экспорт некоторых таблиц в CSV; это не полноценный экспорт всей аналитики в Excel.

**Качество данных:** отсутствие отчёта не считается нулём; неполные, конфликтующие и содержащие замечания периоды выделяются отдельно. Недельные и месячные суммы не распределяются автоматически по дням.

## Импорт Excel

1. Откройте **«Управление» → «Отчёты»** и выберите файл `.xlsx`.
2. Укажите подходящий тип и структуру, если они не распознаны однозначно, а также первую дату или месяц.
3. Нажмите **«Проверить Excel»** и изучите распознанные периоды, контрольные суммы и замечания.
4. Нажмите **«Сохранить отчёты»**. Для опасной замены или сохранения с замечаниями требуется подтверждение.

Поддерживаются два вида исходных таблиц:

- **Обычные отчётные периоды:** повторяющиеся группы столбцов «Работа / Количество / Сумма».
- **Дневные данные за квартал или год:** один общий столбец работ и пары «Количество / Сумма» для отдельных дней; итоговые столбцы проверяются отдельно. Подробнее — [инструкция](docs/DAILY_WIDE_REPORTS.md).

В текущей реализации для широких дневных таблиц **нужны распознаваемые даты** над дневными парами. Год можно указать отдельно; полностью неподписанные дневные пары пока не получают даты автоматически. Расширение импорта без дат, распознавание дат для всех видов отчётов и упрощение поля «Формат Excel» запланированы в [плане развития](docs/ROADMAP.md), а не реализованы.

В Tauri можно выбрать папку Excel, задать правила файлов и получать обновления при изменении источников, пока приложение открыто. Неоднозначные или ошибочные файлы требуют ручной проверки; прежние корректные данные не должны молча заменяться. Удаление файла из папки само по себе не удаляет сохранённый отчёт.

## Где хранятся данные

**Tauri:** SQLite по пути `Документы/Анализ работ/reports.sqlite3` в системной папке документов текущего пользователя. При первом запуске предусмотрен перенос прежних `reports.json` и `desktop-config.json` из той же папки; оригиналы не удаляются. Самостоятельная браузерная версия использует собственное хранилище и не синхронизирует его с SQLite автоматически.

**Резервные копии:** сохраняйте полную копию через «Управление» → «Настройки» в отдельном месте, особенно перед импортом большого массива или переходом между версиями. **Автоматические снимки SQLite и синхронизация общей SQLite между компьютерами пока не реализованы.** Возможные улучшения описаны в [плане развития](docs/ROADMAP.md).

Excel, база отчётов и настройки не отправляются на внешний сервер. Интернет используется для проверки и загрузки подписанных обновлений Tauri, если механизм настроен.

## Разработка и проверки

Сборка Tauri и Windows-проверка описаны в [tauri/README.md](tauri/README.md). Для текущих исходников предусмотрены:

```text
node --test tauri/tests/*.test.cjs tests/*.cjs desktop/core.test.cjs
python -m unittest discover -s tests -v
cargo test --manifest-path tauri/src-tauri/Cargo.toml
```

Для локальной сборки 0.1.3 прошли **111 Node-тестов**, **40 браузерных проверок Chromium** и **14 Rust-тестов исходного модуля SQLite**. Rust-тесты выполнялись в отдельном Linux-harness с неизменённым `storage.rs`, без Tauri GUI. Полный запуск нового приложения в Windows, импорт и повторный запуск с пользовательской базой остаются непроверенными.

Браузерные тесты требуют Playwright и Chromium, Rust-тесты — Rust toolchain. Windows GUI-тест работает на Windows runner и проверяет установленную тестовую сборку с WebView2.

[Windows CI #44004089459](https://github.com/v2029944-ui/HTML-test/actions/runs/44004089459) успешно проверил 111 Node-тестов, 14 Rust-тестов и GUI-сценарии (импорт 366 дней, SQLite, календарь и перезапуск) в **отдельной тестовой сборке**. Это не проверка на пользовательском компьютере и не испытание реального рабочего Excel.

## Дальнейшая разработка

В [плане развития](docs/ROADMAP.md) предусмотрены улучшения импорта, выбор недель и дней в календаре, резервные копии, контроль источников, производительность и расширенный экспорт. Это **план**, а не список готовых возможностей.

Для многопользовательской работы через сетевую папку пока нет встроенного механизма публикации и получения общей SQLite: такую архитектуру нужно разработать и проверить отдельно. Прямое совместное изменение одного файла SQLite по сети не является текущим режимом приложения.
