# HTML-test — автономная аналитика отчётов

Приложение работает полностью локально из одного файла [`index.html`](./index.html). Excel, отчёты и настройки не отправляются на сервер. Для запуска на компьютере достаточно открыть HTML в браузере. Отдельный backend, Node.js, сборка и доступ к сети не требуются.

## Импорт Excel

1. Откройте «Импорт Excel», нажмите **«Выберите файл»**, укажите `.xlsx`, выберите тип, дату начала и лист.
2. Для привычной структуры с горизонтальными тройками «Работа / Количество / Сумма» оставьте автоматическое распознавание. Нажмите «Проверить Excel» перед сохранением.
3. Для нестандартных листов откройте **«Столбцы и даты каждого набора»** → **«Указать столбцы вручную»**. Для каждого набора введите буквы столбцов работы, количества и суммы и номер строки заголовка. Столбцы не обязаны быть соседними. «Добавить набор столбцов» создаёт ещё один отчётный блок.
4. В том же разделе можно изменить дату каждого найденного набора отдельно. Без изменений даты считаются последовательными от первой недели или месяца. Пересекающиеся даты внутри импорта отклоняются.
5. Сверьте предпросмотр, замечания и контрольные суммы. Не исправляйте расхождения подгонкой чисел в приложении.

Ограничение: встроенный XLSX-парсер поддерживает известные структуры ZIP/XML, а не все возможности Excel. Ручной маппинг помогает с расположением колонок, но не заменяет диагностику формул и неподдерживаемых форматов.

## Контроль качества

В «Контроле качества данных» показываются строка и известный адрес ячейки Excel, например `Лист1!B27`. Для новых импортов доступно раскрываемое «Как проверить и исправить» и копирование адреса. Для расхождений итога адрес относится к **контрольной ячейке** — сама ошибка может находиться среди работ выше. Ранее сохранённые отчёты без координат не получают вымышленных адресов.

## Сравнение подразделений в графиках

Откройте **«Аналитика → Подробный анализ → Графики и сравнение подразделений»**. В поле **«Сравнивать»** выберите **«Подразделения»**. Линейный график, столбцы и таблица отображают выбранные подразделения по общему диапазону недель или месяцев. Используются подразделения и показатели из основных фильтров; сумма и количество показаны отдельно.

В поле **«Показатели для графика»** можно выбрать сумму, количество и среднюю сумму на работу (в любом сочетании). Каждая комбинация подразделения и показателя — отдельная серия: два подразделения × три показателя = шесть линий или столбцов на одном графике. По умолчанию выбраны все три показателя; «Отображение» переключает на отдельные графики по показателям с исходными шкалами.

**Шкала совместного графика:** величины с разными единицами показываются в процентах от максимального по модулю значения **своего показателя** за выбранный диапазон. Это не процент роста. Точные числа доступны в подсказках и таблице. Отрицательные значения расположены ниже нуля, отсутствие данных не заменяется нулём. Если выбран один показатель или раздельные графики, используется его исходная шкала.

Поле **«Какие работы учитывать»** задаёт расчёт: **все выполненные работы** (по умолчанию) либо **только отмеченные работы и группы**. Под графиками отображается таблица общих итогов и количества полных отчётных периодов каждого подразделения. Если отчёт подразделения отсутствует хотя бы в одном периоде диапазона, его итог за диапазон обозначается прочерком; на графике пропущенная точка не считается нулём.

Прежний режим «Работы и группы» остался доступен в том же переключателе. Для отдельного табличного сравнения относительно базового подразделения можно использовать соседний раздел **«Сравнение»**.

## Календарь отчётов

На вкладке «Импорт Excel» расположена сетка из 12 недель либо 12 месяцев с кнопками «Раньше/Позже». Отмечаются загруженные, неполные, проблемные и отсутствующие периоды. При выборе периода можно просмотреть источник и перейти к проверке качества. Отсутствующий отчёт никогда не превращается в нулевой показатель.

## Сводка для печати

В разделе «Аналитика → Обзор работы» нажмите **«Печать сводки / PDF»**. Формируется отдельный печатный лист с итогами, результатами подразделений, сравнением с предыдущим равным интервалом и крупнейшими изменениями. В открывшемся диалоге браузера выберите принтер или «Сохранить как PDF». Неполные данные и замечания источника обозначаются отдельно. Дополнительные библиотеки для экспорта не используются.

## Локальное хранение и резервные копии

Отчёты сохраняются в IndexedDB браузера, при недоступности — в ограниченном localStorage. Если запись отклонена браузером или переполнено хранилище, приложение выводит ошибку; прежний набор отчётов не подменяется ложным успешным сохранением. Восстановление полной копии, переименование подразделений и импорт отчётов вместе со справочником выполняются одной транзакцией. Устройство и браузер **не синхронизируются автоматически**. Регулярно скачивайте полную JSON-копию в «Данные и настройки».

## Ограничения и проверка

- Рабочая программа остаётся одним `index.html` и не требует внешних зависимостей.
- Ручная группировка услуг сохраняется; автоматической группировки нет.
- История импортов и сохранённые наборы фильтров не добавлялись.
- Локально изолированно проверены функции Excel-мэппинга, непоследовательные даты, отбрасывание пересечений, адреса ячеек, календарные статусы, печатная сводка и успешные/неуспешные транзакции.
- Перед рабочим применением нужно отдельно проверить полный импорт реального Excel, сохранение после закрытия браузера, печать и экранные размеры 320–1440 px. Физический iPhone/Safari и запуск через `file://` не были проверены автоматическим браузерным тестом.

## Локальные проверки интерфейса — 14.11.2026

Поле «Начало первой недели» и выбор месяца уже ограничены общей высотой соседних списков и шириной контейнера; нативный календарь сохранён. Код приложения при этом обновлении не переписывался.

В `tests/test_import_controls.py` закреплены две браузерные проверки: пустые/заполненные дата и месяц на 320/375/390/428/1024 px; условная видимость фильтра графика и CSV с суммой, дробным количеством и отсутствующим отчётом (пропуск не заменяется нулём). Фикстуры синтетические, рабочих Excel-файлов в тестах нет.

Команда разработчика: `python -m unittest discover -s tests -v`. Нужны Python, пакет Playwright и системный Chromium `/usr/bin/chromium`; пользователю приложения они не требуются. HTML подаётся через перехват запроса Playwright, без сервера и внешних запросов. GitHub Actions не запускаются. Проверки выполнены в Chromium; Safari/iPhone и его нативный календарь отдельно не проверены. В Chromium исходное превышение размера поля не воспроизвелось — тесты проверяют его границы и сохранение выбора даты.
