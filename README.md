Приложение локально анализирует Excel-отчёты о работах: количество/объём, суммы, подразделения, группы, периоды, сравнения и отклонения. Основная платформа — Windows на Tauri 2 + SQLite; автономный `index.html` остаётся доступен.

## Что доступно в Tauri 0.1.5

- Классические аналитика, группы работ, графики, сравнение периодов и подразделений, контроль качества и адреса проблемных ячеек. CSV из таблиц и печать сводки/PDF через диалог печати.
- **Отдельный SQL-режим**: постраничное чтение больших наборов, SQL-аналитика, сравнения, экспорт CSV. Классический интерфейс сохранён и **может загружать историю целиком в память**.
- Проверяемый **нативный импорт широких дневных XLSX** и SQLite Online Backup перед потенциально опасной заменой.
- **Новое в 0.1.5:** дополнительные виды отчётов, в том числе «трудозатраты/выработка» и «план/факт», собственные исходные/расчётные показатели и встроенные профили **простых построчных XLSX** с предварительным просмотром и подтверждением. Для изменения JSON-профилей нужна пересборка. [Описание](docs/EXTENSIBLE_REPORT_KINDS.md).
- **Новое в 0.1.5:** [офлайн-проверка восстановления SQLite в отдельную копию](docs/SQLITE_RECOVERY_DRILL.md), в том числе с WAL. Встроенной кнопки восстановления рабочей базы и отката импорта пока нет.

**Обновление:** сделайте отдельную резервную копию SQLite и исходных Excel, закройте программу, установите EXE вручную и проверьте знакомые отчёты. Приложение в активной разработке: совместимость с предыдущими экспериментальными версиями и автоматическая миграция не гарантируются; не заменяйте базу вручную при работающем приложении.

Предыдущая [0.1.4](https://github.com/v2029944-ui/HTML-test/releases/tag/tauri-v0.1.4) сохранена в истории, но больше не является актуальным выпуском.

## Интерфейс

Основные разделы — **«Аналитика»** и **«Анализ изменений»**. В меню **«Управление»** находятся **«Отчёты»**, **«Группы работ»** и **«Настройки»**. На узких экранах используется компактное меню.

- Аналитика: итоги, графики, сравнение подразделений и периодов, динамика работ, структура и частота услуг, отклонения от обычных значений.
- Анализ изменений: поиск, направления роста и снижения, пороги, сравнение с предыдущим периодом или внутри диапазона.
- Группы работ: ручной состав групп, справочник, проверка и импорт/экспорт JSON.
- Отчёты: импорт Excel, календарь по месяцам с просмотром дней, список загруженных отчётов, контроль качества и исходные ячейки ошибок.
- Итоги за период можно распечатать или сохранить как PDF через диалог печати. Доступен экспорт некоторых таблиц в CSV; это не полноценный экспорт всей аналитики в Excel.

**Качество данных:** отсутствие отчёта не считается нулём; неполные, конфликтующие и содержащие замечания периоды выделяются отдельно. Недельные и месячные суммы не распределяются автоматически по дням.

## Импорт Excel

1. Откройте **«Управление» → «Отчёты»** и выберите файл `.xlsx`.
2. Укажите подходящий тип и структуру, если они не распознаны однозначно, а также первую дату или месяц.
3. Нажмите **«Проверить Excel»** и изучите распознанные периоды, контрольные суммы и замечания.
4. Нажмите **«Сохранить отчёты»**. Для опасной замены или сохранения с замечаниями требуется подтверждение.

Поддерживаются два вида исходных таблиц:

- **Обычные отчётные периоды:** повторяющиеся группы столбцов «Работа / Количество / Сумма».
- **Дневные данные за квартал или год:** один общий столбец работ и пары «Количество / Сумма» для отдельных дней; итоговые столбцы проверяются отдельно. Подробнее — [инструкция](docs/DAILY_WIDE_REPORTS.md).
- **Дополнительные отчёты 0.1.5 в SQL-режиме:** простые построчные XLSX по встроенному профилю (например, «Подразделение / Работа / Часы / Объём» или «Подразделение / Показатель / План / Факт»). Нужны выбор профиля, даты, предпросмотр и подтверждение. [Инструкция](docs/EXTENSIBLE_REPORT_KINDS.md).

В текущей реализации для широких дневных таблиц **нужны распознаваемые даты** над дневными парами. Год можно указать отдельно; полностью неподписанные дневные пары пока не получают даты автоматически. Расширение импорта без дат, распознавание дат для всех видов отчётов и упрощение поля «Формат Excel» запланированы в [плане развития](docs/ROADMAP.md), а не реализованы.

В Tauri можно выбрать папку Excel, задать правила файлов и получать обновления при изменении источников, пока приложение открыто. Неоднозначные или ошибочные файлы требуют ручной проверки; прежние корректные данные не должны молча заменяться. Удаление файла из папки само по себе не удаляет сохранённый отчёт.

## Где хранятся данные

**Tauri:** SQLite по пути `Документы/Анализ работ/reports.sqlite3` в системной папке документов текущего пользователя. При первом запуске предусмотрен перенос прежних `reports.json` и `desktop-config.json` из той же папки; оригиналы не удаляются. Самостоятельная браузерная версия использует собственное хранилище и не синхронизирует его с SQLite автоматически.

**Резервные копии:** используйте «Управление» → «Настройки» и храните копию отдельно. SQLite Online Backup уже защищает отдельные сценарии замены; **периодических снимков с политикой хранения, встроенного восстановления рабочей базы и сетевой синхронизации пока нет**. Офлайн-инструмент создаёт только проверяемую восстановленную копию. [План](docs/ROADMAP.md).

Excel, база отчётов и настройки не отправляются на внешний сервер. Интернет используется для проверки и загрузки подписанных обновлений Tauri, если механизм настроен.

## Разработка и проверки

Сборка Tauri и Windows-проверка описаны в [tauri/README.md](tauri/README.md). Для текущих исходников предусмотрены:

```text
node --test tauri/tests/*.test.cjs tests/*.cjs
python -m unittest discover -s tests -v
cargo test --manifest-path tauri/src-tauri/Cargo.toml
```

Для **0.1.5** успешно завершился [Windows CI #44326123850](https://github.com/v2029944-ui/HTML-test/actions/runs/44326123850) на точном коммите выпуска `c0f235a7ddf5938185084b5b7dd930e7cb0de508`: Node/Rust, SQLite, XLSX, NSIS и тест установленного приложения в WebView2. [Публикация GitHub Release](https://github.com/v2029944-ui/HTML-test/actions/runs/44328671462) также прошла успешно. Это преимущественно синтетические проверки, не тесты реальных пользовательских Excel.

Браузерные тесты требуют Playwright и Chromium, Rust-тесты — Rust toolchain. Windows GUI-тест работает на Windows runner и проверяет установленную тестовую сборку с WebView2.

Историческая бета-проверка: [Windows CI #44004089459](https://github.com/v2029944-ui/HTML-test/actions/runs/44004089459) успешно проверил 111 Node-тестов, 14 Rust-тестов и GUI-сценарии (импорт 366 дней, SQLite, календарь и перезапуск) в **отдельной тестовой сборке**. Это не проверка на пользовательском компьютере и не испытание реального рабочего Excel.

## Дальнейшая разработка

[Общий план развития](docs/ROADMAP.md) сохраняет задачи импорта, календаря, резервирования, контроля источников, производительности и экспорта. [Подробный план после 0.1.5](docs/UX_DATA_IMPLEMENTATION_PLAN.md) объединяет новые и предыдущие замечания: понятные ошибки, восстановление SQLite, имена работ и единицы, графики, фильтры, главный экран, профили Excel и план/факт. **Планируемые возможности ещё не реализованы.**

Для многопользовательской работы через сетевую папку пока нет встроенного механизма публикации и получения общей SQLite: такую архитектуру нужно разработать и проверить отдельно. Прямое совместное изменение одного файла SQLite по сети не является текущим режимом приложения.
