# Windows-приложение HTML-test — Tauri 2 + SQLite

Tauri использует системный WebView2 на Windows и интерфейс [index.html](../index.html) для работы с отчётами Excel. Основные данные сохраняются **локально в SQLite**, а не в браузере или в постоянно перезаписываемом JSON.

## Версии и установка

- **Опубликованная подписанная версия:** [Tauri 0.1.2, Windows x64](https://github.com/v2029944-ui/HTML-test/releases/download/tauri-v0.1.2/Analiz-rabot-Tauri-Windows-x64-setup.exe).
- В исходном коде может находиться следующая экспериментальная версия, ещё не опубликованная как обновление для пользователей. Номер `tauri.conf.json` не следует считать номером доступного релиза.
- [Tauri 0.1.3-beta.1: отчёт о Windows GUI-проверке](../docs/TAURI_PREVIEW.md). Тестовая сборка не публикуется в канал `tauri-updates`.

Подписанный выпуск Tauri 0.1.1 может получать 0.1.2 через встроенную проверку обновлений. Новые версии скачиваются и устанавливаются **только после подтверждения**. Перед обновлением рекомендуется создать отдельную резервную копию отчётов. Поддерживается работа без интернета; для проверки обновлений сеть нужна.

Наличие [старого Electron](../desktop/README.md) в репозитории связано с совместимостью и незавершённой очисткой [PR #13](https://github.com/v2029944-ui/HTML-test/pull/13), а не с выбором архитектуры для будущей разработки.

## Устройство программы

- `../index.html` — исходная автономная браузерная версия. При сборке она не меняется.
- `prepare.cjs` — создаёт `tauri/web/` и добавляет только в эту копию Tauri-скрипты.
- `bridge.js` — совместимый интерфейс `window.desktopAPI` к Rust-командам и SQLite.
- `updates.js` — интерфейс проверки и подтверждения подписанных обновлений.
- `../desktop/renderer.js` — пока ещё общий модуль импорта из папки, используемый Tauri через `prepare.cjs`. Перенос в `tauri/` предложен в PR #13; удалять файл до переноса нельзя.
- `src-tauri/src/storage.rs` и `src-tauri/src/main.rs` — SQLite, миграция, работа с папками и команды приложения.

База пользователя: **`Документы/Анализ работ/reports.sqlite3`** (системный каталог документов). На первом запуске возможен перенос старых `reports.json` и `desktop-config.json` из этого же каталога. Исходные JSON не удаляются и не изменяются, если перенос завершён или произошла ошибка.

Изменение данных выполняется транзакционно. При неверном формате, конфликте источников, отсутствии подтверждения или ошибке импорта ранее сохранённые корректные отчёты не должны незаметно заменяться.

### Импорт из выбранной папки

1. В «Управление» → «Отчёты» выберите папку Excel.
2. Настройте тип, начальный период и при необходимости лист или структуру для обнаруженных файлов.
3. При изменении XLSX программа проверяет папку приблизительно раз в три секунды **пока приложение открыто**; сканирование также происходит после запуска.
4. «Проверить и сохранить вручную» открывает существующий предпросмотр. При проблемах автозагрузка отказывается от замены; ручное сохранение требует просмотра и подтверждения.

Текущий формат: обычные повторяющиеся тройки «Работа / Количество / Сумма» либо широкий дневной отчёт с общим столбцом работ. Подробности дат, пустых значений, итогов, выбранных листов и лимитов XLSX — в [инструкции дневного импорта](../docs/DAILY_WIDE_REPORTS.md).

**Не реализованы:** прямое общее редактирование SQLite несколькими компьютерами через сетевой каталог, автоматическая публикация единой базы для читателей и автоматические SQLite-снимки по расписанию. Эти функции требуют отдельного проекта и проверок.

## Сборка Windows

Для сборки нужны Windows 10/11 x64, WebView2, Node.js 24, Rust и Microsoft C++ Build Tools. Выполните из корня репозитория:

```powershell
npm install --prefix tauri
node --test tauri/tests/*.test.cjs tests/*.cjs desktop/core.test.cjs
npm --prefix tauri run prepare:frontend
npm --prefix tauri run icons
cargo test --manifest-path tauri/src-tauri/Cargo.toml
npm --prefix tauri run build:windows
```

Готовый NSIS-установщик появляется в `tauri/src-tauri/target/release/bundle/nsis/`. Команда `build:windows` создаёт локальную сборку без настройки публикации обновлений. Тесты `desktop/core.test.cjs` остаются в команде, пока существующий общий модуль не перенесён по PR #13.

### Подписанные обновления

Подписи проверяет Tauri Updater. Манифест канала опубликован как отдельный prerelease [`tauri-updates`](https://github.com/v2029944-ui/HTML-test/releases/tag/tauri-updates); он не является обычным релизом приложения.

- `ANALIZ_UPDATER_PUBLIC_KEY` — открытый ключ проверки.
- `TAURI_SIGNING_PRIVATE_KEY` — закрытый ключ подписи (секрет; не хранить в репозитории или артефактах).
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль ключа, если используется.

Для подписанной сборки выполните `npm --prefix tauri run build:signed:windows` с корректно настроенными секретами. Скрипт `release.cjs` формирует установщик, `.sig` и `tauri-latest.json`, **но сам ничего не публикует**. Публикация выполняется отдельно после подтверждения владельца, с проверкой версии и подписи. Существующие опубликованные установщики не следует перезаписывать новой сборкой с тем же номером.

GitHub Actions: `.github/workflows/tauri-windows.yml` (Windows-сборка и тесты) и `.github/workflows/tauri-signed-release.yml` (подписанный релиз при разрешённых условиях). Подробные правила выпуска — в этих workflow и `publish.cjs`. Не отправляйте в репозиторий закрытые ключи или их копии.

## Результаты и ограничения проверки

[Windows CI #44004089459](https://github.com/v2029944-ui/HTML-test/actions/runs/44004089459) завершился успешно: **111 Node-тестов**, **14 Rust-тестов** и GUI-тест установленного приложения в WebView2 156. Проверены импорт синтетического XLSX на 366 дней, запись/повторное чтение SQLite, выбор дней февраля 2024, клавиатура списков и сохранение данных после штатного перезапуска.

Для GUI-автоматизации использована **отдельная непубликуемая тестовая сборка** с отладочным портом; пользовательский подписанный установщик создаётся отдельно и не содержит этот порт. Отчёт о точных ограничениях и предыдущих неуспешных запусках — [docs/TAURI_PREVIEW.md](../docs/TAURI_PREVIEW.md).

Физический пользовательский Windows 10/11, реальные рабочие Excel и установка реального онлайн-обновления между двумя подписанными версиями требуют дополнительной проверки. Не считайте успешную проверку синтетического XLSX гарантией совместимости с любым файлом Excel. При больших наборах данных производительность фронтенда также стоит измерять отдельно.
