# Анализ работ 0.1.5 — актуальная Windows-версия (Tauri 2 + SQLite)

Tauri использует системный WebView2 на Windows и интерфейс [index.html](../index.html). Основные данные сохраняются локально в SQLite в папке «Документы/Анализ работ».

## Версия 0.1.5 и установка

**[Скачать установщик 0.1.5 для Windows x64](https://github.com/v2029944-ui/HTML-test/releases/download/tauri-v0.1.5/Analiz-rabot-0.1.5-Windows-x64-setup.exe)** — 5 283 725 байт, NSIS, не подписан для Tauri Updater.

[GitHub Release — Latest](https://github.com/v2029944-ui/HTML-test/releases/tag/tauri-v0.1.5) · [SHA-256](https://github.com/v2029944-ui/HTML-test/releases/download/tauri-v0.1.5/SHA256SUMS.txt) · [заметки к 0.1.5](release-notes/0.1.5.md) · [Windows CI/WebView2](https://github.com/v2029944-ui/HTML-test/actions/runs/44326123850).

**Состав:** классическая аналитика и локальная SQLite; отдельный SQL-режим с постраничным чтением, аналитикой и CSV; проверяемый нативный импорт широких XLSX; SQLite Online Backup перед заменой. В 0.1.5 добавлены **конфигурируемые виды отчётов** (включая «план/факт» и трудозатраты), построчные XLSX-профили и **офлайн-проверка восстановления SQLite в отдельную копию**.

**Установка:** сделайте независимую резервную копию базы и исходных Excel, закройте программу, установите EXE и проверьте известные периоды, группы и итоги. Обратная совместимость с экспериментальными версиями и автоматический перенос не гарантируются. Кнопки восстановления рабочей базы ещё нет; не заменяйте SQLite-файл при работающем приложении.

**Важно:** 0.1.5 отмечена в GitHub как **Latest**, но доступна для **ручной установки**. Канал подписанных обновлений `tauri-updates` не переключался на 0.1.5. Исторический [релиз 0.1.4](https://github.com/v2029944-ui/HTML-test/releases/tag/tauri-v0.1.4) остаётся доступен.

## Переход к основному SQL-интерфейсу (этап 1)

В Tauri подготовлен переключаемый запуск **без загрузки всей истории в WebView**. В отдельном SQL-режиме отметьте **«Открывать SQL-режим при запуске программы»**: при следующем старте приложение откроет его напрямую. Это предпочтение не изменяет SQLite и отменяется той же галочкой.

Пока по умолчанию запускается классический интерфейс: перенос импорта, расширенных графиков и оставшихся экранов в SQL ещё не завершён. Из SQL-режима можно перейти в «Классический интерфейс и импорт Excel». Автономный HTML не затронут.

[Подробности и дальнейшие этапы](../docs/SQL_MIGRATION.md).

## Дополнительные виды отчётов в 0.1.5

Новые виды отчётов конфигурируются двумя каталогами:

- `src-tauri/src/metric-kinds.json` — виды отчётов, исходные и вычисляемые показатели, единицы;
- `src-tauri/src/metric-xlsx-profiles.json` — листы, заголовки и соответствие колонок простого построчного XLSX.

Для нового вида и структуры колонок достаточно обновить конфигурацию и **пересобрать** приложение; новый Rust-парсер не нужен для поддерживаемой построчной структуры. Пользователь выбирает профиль и даты, просматривает результат и подтверждает импорт. Пользовательского визуального конструктора профилей пока нет; классическая аналитика и новые виды отчётов пока разделены.

[Инструкция и ограничения](../docs/EXTENSIBLE_REPORT_KINDS.md) · [PR #42, уже включён в 0.1.5](https://github.com/v2029944-ui/HTML-test/pull/42) · [план улучшений UX и данных](../docs/UX_DATA_IMPLEMENTATION_PLAN.md).

## Устройство программы

- `../index.html` — исходная автономная браузерная версия. При сборке она не меняется.
- `prepare.cjs` — создаёт `tauri/web/` и добавляет только в эту копию Tauri-скрипты.
- `bridge.js` — совместимый интерфейс `window.desktopAPI` к Rust-командам и SQLite.
- `updates.js` — интерфейс проверки и подтверждения подписанных обновлений.
- `folder-importer.js` — модуль импорта Excel из выбранной папки. При подготовке frontend он включается только в Tauri; автономная HTML-версия не изменяется.
- `src-tauri/src/storage.rs` и `src-tauri/src/main.rs` — SQLite, миграция, работа с папками и команды приложения.
- `import-core/` — ограниченный дисковый Rust-парсер XLSX с временной SQLite, используемый для широких дневных файлов и дополнительных построчных профилей. Запись в рабочую базу требует проверки и подтверждения. [Подробности широкого импорта](../docs/NATIVE_WIDE_REVIEWED_IMPORT.md).

База пользователя: **`Документы/Анализ работ/reports.sqlite3`** (системный каталог документов). На первом запуске возможен перенос старых `reports.json` и `desktop-config.json` из этого же каталога. Исходные JSON не удаляются и не изменяются, если перенос завершён или произошла ошибка.

Изменение данных выполняется транзакционно. При неверном формате, конфликте источников, отсутствии подтверждения или ошибке импорта ранее сохранённые корректные отчёты не должны незаметно заменяться.

### Импорт из выбранной папки

1. В «Управление» → «Отчёты» выберите папку Excel.
2. Настройте тип, начальный период и при необходимости лист или структуру для обнаруженных файлов.
3. При изменении XLSX программа проверяет папку приблизительно раз в три секунды **пока приложение открыто**; сканирование также происходит после запуска.
4. «Проверить и сохранить вручную» открывает существующий предпросмотр. При проблемах автозагрузка отказывается от замены; ручное сохранение требует просмотра и подтверждения.

Текущий формат: обычные повторяющиеся тройки «Работа / Количество / Сумма» либо широкий дневной отчёт с общим столбцом работ. Подробности дат, пустых значений, итогов, выбранных листов и лимитов XLSX — в [инструкции дневного импорта](../docs/DAILY_WIDE_REPORTS.md).

**Не реализованы:** прямое общее редактирование SQLite несколькими компьютерами через сетевой каталог, автоматическая публикация единой базы для читателей и автоматические SQLite-снимки по расписанию. Эти функции требуют отдельного проекта и проверок.

## Сборка Windows

Средства ниже нужны разработчику для сборки, а не пользователю для установки готового EXE. GitHub Actions не обязателен: [проверенный способ кросс-сборки из Linux](../docs/TAURI_WITHOUT_ACTIONS.md) описан отдельно.

Для сборки нужны Windows 10/11 x64, WebView2, Node.js 24, Rust и Microsoft C++ Build Tools. Выполните из корня репозитория:

```powershell
npm install --prefix tauri
node --test tauri/tests/*.test.cjs tests/*.cjs
npm --prefix tauri run prepare:frontend
npm --prefix tauri run icons
cargo test --manifest-path tauri/src-tauri/Cargo.toml
npm --prefix tauri run build:windows
```

Готовый NSIS-установщик появляется в `tauri/src-tauri/target/release/bundle/nsis/`. Команда `build:windows` создаёт локальную сборку без настройки публикации обновлений. Тесты папочного импорта находятся в `tests/test_folder_importer.cjs`; устаревшие Electron-тесты исключены.

### Подписанные обновления

**Установщик 0.1.5 опубликован как Latest для ручной установки и не подписан; канал автоматических обновлений не изменялся.** Простая сборка EXE не публикует онлайн-обновление.

Подписи проверяет Tauri Updater. Манифест канала опубликован как отдельный prerelease [`tauri-updates`](https://github.com/v2029944-ui/HTML-test/releases/tag/tauri-updates); он не является обычным релизом приложения.

- `ANALIZ_UPDATER_PUBLIC_KEY` — открытый ключ проверки.
- `TAURI_SIGNING_PRIVATE_KEY` — закрытый ключ подписи (секрет; не хранить в репозитории или артефактах).
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль ключа, если используется.

Для подписанной сборки выполните `npm --prefix tauri run build:signed:windows` с корректно настроенными секретами. Скрипт `release.cjs` формирует установщик, `.sig` и `tauri-latest.json`, **но сам ничего не публикует**. Публикация выполняется отдельно после подтверждения владельца, с проверкой версии и подписи. Существующие опубликованные установщики не следует перезаписывать новой сборкой с тем же номером.

Выпуск 0.1.5 размещён после успешной Windows-проверки посредством `.github/workflows/tauri-015-current-release.yml`: создал GitHub Latest и приложил неподписанный NSIS и SHA-256, не меняя updater. Для 0.1.4 использовался `.github/workflows/tauri-014-manual-prerelease.yml`. Подписанные будущие обновления предусмотрены в `.github/workflows/tauri-signed-release.yml` и `publish.cjs`; не отправляйте в репозиторий закрытые ключи или их копии.
