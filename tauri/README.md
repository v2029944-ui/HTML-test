# Tauri 2 + SQLite — переходная ветка (экспериментальная сборка)

Эта версия создаётся **параллельно** работающему Electron и исходному `index.html`. Никакие существующие файлы удалять не требуется. Это первый этап переноса, пока **не** основная версия для повседневного использования.

## Что уже реализовано

- Отдельная оболочка Tauri 2 с использованием системного WebView2 на Windows.
- Исходный HTML остаётся неизменным; `prepare.cjs` создаёт его копию в `tauri/web/` и добавляет Tauri API только в неё.
- Сохраняется текущая логика анализа, графиков и чтения Excel, а также визуальная часть управления папкой из `desktop/renderer.js`.
- Поддерживаются **дневные, недельные и месячные** отчёты из актуального HTML-test. При обновлении исходного интерфейса Tauri заново копирует `index.html` и `desktop/renderer.js`; автоматический тест сравнивает типы периодов в HTML и Rust/SQLite, чтобы они не расходились.
- Локальная SQLite-база `reports.sqlite3` вместо браузерной IndexedDB и многократно переписываемого файла JSON.
- Операции сохранения отчётов выполняются транзакционно; индексы предусмотрены по периоду и источнику.
- При переносе данных из прежнего Electron поддерживаются смешанные отчёты всех трёх типов. Неверные или неизвестные типы приводят к отказу от сохранения без изменения уже записанных данных.
- При первом открытии новой базы, если в прежней папке есть `reports.json` и `desktop-config.json`, они копируются в SQLite. **Прежние JSON-файлы не удаляются и не изменяются.** Если миграция не удалась, запись блокируется до исправления проблемы.
- Сканирование выбранной папки XLSX примерно раз в 3 секунды, повторное сканирование при запуске, проверка размера/типа и сохранение последних корректных данных при ошибках импорта.

Путь к базе: системная папка **«Документы / Анализ работ / reports.sqlite3»**, рядом с предыдущими `reports.json`. За пределы этого каталога база сама не сохраняется; Excel читает только из папки, выбранной пользователем.

## Сборка и проверка

На Windows 10/11 x64 с установленным WebView2, Rust, Microsoft C++ Build Tools и Node.js 24:

```powershell
npm install --prefix tauri
node --test tauri/tests/prepare.test.cjs
npm --prefix tauri run prepare:frontend
npm --prefix tauri run icons
cargo test --manifest-path tauri/src-tauri/Cargo.toml
npm --prefix tauri run build:windows
```

Готовый установщик Tauri (при успешной сборке) расположен в `tauri/src-tauri/target/release/bundle/nsis/`. Он создаётся отдельно от Electron Release и пока доступен только в CI-сборке ветки.

## Обязательные проверки до перехода на Tauri

1. Импорт реального Excel и сравнение расчётов с браузерной версией по нескольким подразделениям и периодам.
2. Миграция настоящих `reports.json` и `desktop-config.json` на копиях данных, проверка сохранности старой базы при сбое.
3. Работа файлового диалога, фонового обновления и открытия каталога через системный WebView2 на Windows.
4. Сравнение размера и времени запуска с Electron, испытания на большом объёме отчётов.
5. Онлайн-обновления: механизм Tauri Updater добавлен; перед включением необходимы ключ подписи и публикация подписанного выпуска по инструкции ниже. Без этого экспериментальная сборка не предлагает установку.
6. Оптимизация операций с сотнями тысяч строк: пока фронтенд получает полный список отчётов через API, хотя SQLite уже хранит их по отдельности. Перевод аналитики на выборочные запросы — отдельная задача.

До завершения проверок **не заменяйте установленную Electron-программу**. Исходный HTML и Electron остаются доступными.

## Схема

```text
index.html               исходная веб-версия (не изменена)
desktop/                 Electron, существующая версия
tauri/prepare.cjs        сборка копии HTML только для Tauri
tauri/bridge.js          совместимый JS-интерфейс к командам Rust
tauri/src-tauri/src/     Rust-команды, SQLite, работа с папками
Документы/Анализ работ/  база и ранее импортированные отчёты (данные не в репозитории)
```



## Ручная проверка файла из папки

У каждого найденного файла появилась кнопка «Проверить и сохранить вручную». Укажите тип периода, первую дату и при необходимости лист; кнопка загрузит файл из выбранной папки в существующий предпросмотр ниже, без повторного выбора через системное окно. Ничего не сохраняется при открытии предпросмотра. «Сохранить отчёты» запрашивает подтверждение при замечаниях; «Отмена» сохраняет прежние данные. Для замены совпадающих периодов нужен существующий флажок замены.

Замечания, пропущенные строки, исходные координаты и расхождения итогов остаются в отчёте и контроле качества. Показатели не исправляются автоматически. Пустой отчёт и повреждённый XLSX по-прежнему не могут быть сохранены обычной кнопкой. Автоимпорт продолжает отклонять отчёты с замечаниями.

Пока открыта ручная проверка из папки, автоимпорт приостановлен, чтобы не менять сохранённые данные во время подтверждения. Для возврата к нему нажмите «Закрыть ручную проверку», сохраните отчёты либо выберите другой файл. Перед сохранением проверяются папка, правило и подпись изменения исходного файла. Если они изменились, нужно открыть свежую проверку.

Если даты, тип, лист и автоматическое распознавание соответствуют сохранённому правилу папки, отчёт сохраняет существующие метки источника для последующего автообновления. При собственных датах или ручном сопоставлении столбцов сохраняется обычный независимый отчёт: будущий автоимпорт не должен молча его заменять. Для постоянной настройки сначала сохраните правильное правило файла.

## Онлайн-обновления Tauri

В настройках Tauri добавлен блок «Обновление программы». При запуске подписанной сборки выполняется проверка версии; можно повторить её вручную. Скачивание и установка начинаются только после «Скачать и установить» и подтверждения. Показывается ход загрузки. Плагин Tauri проверяет цифровую подпись до установки; ошибка сети или подписи выводится пользователю. На время установки программа закрывается, штатный установщик заменяет файлы приложения и запрашивает последующий запуск. Отчёты SQLite, старые JSON и исходные Excel вне каталога программы не удаляются. Произвольная очистка пользовательских папок не выполняется.

Обновления Tauri отделены от Electron: статический канал — `https://github.com/v2029944-ui/HTML-test/releases/download/tauri-updates/tauri-latest.json`. Он ещё должен быть опубликован владельцем. Неподписанные экспериментальные сборки сообщают, что обновления не настроены. Проверка обновлений требует интернета; остальная аналитика остаётся локальной.

### Первый подписанный выпуск (Windows, выполняет владелец)

1. В каталоге `tauri` установите зависимости: `npm install`. Создайте ключ **вне репозитория** командой `npx tauri signer generate -w "$env:USERPROFILE\.tauri\analiz.key"` в PowerShell. Сохраните закрытый ключ и пароль в надёжном месте: потеря ключа лишает возможности обновлять уже установленные выпуски. Закрытый ключ и пароль не передавайте в чат и не публикуйте в GitHub.
2. Перед сборкой задайте `ANALIZ_UPDATER_PUBLIC_KEY` содержимым файла `.pub`, `TAURI_SIGNING_PRIVATE_KEY` — путём к закрытому ключу (или его содержимым по правилам Tauri CLI), `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — паролем ключа. Переменные должны быть доступны только локальному процессу сборки. В исходный код попадает только открытый ключ.
3. Согласованно увеличьте версию в `tauri/package.json`, `tauri/src-tauri/Cargo.toml` и `tauri/src-tauri/tauri.conf.json`. Выполните `npm run build:signed:windows` из `tauri`. Команда собирает установщик и его подпись, затем создаёт `tauri/release/tauri-v<версия>/` с установщиком, `.sig` и `tauri-latest.json`. Не используйте другой ключ для последующих выпусков. Каталог исключён из Git.
4. Опубликуйте установщик и `.sig` в GitHub Release с тегом `tauri-v<версия>`. Отдельный постоянный Release с тегом `tauri-updates` содержит только актуальный `tauri-latest.json`: заменяйте его **после** публикации установщика. Отметьте Tauri-релизы как prerelease, пока версия экспериментальная; так они не изменят ссылку `releases/latest` на Electron. Скрипт сборки сам не создаёт коммиты, релизы и Actions.
5. Первый выпуск с механизмом обновления нужно установить один раз вручную: ранее собранный EXE сам новую функцию не получит. Последующие версии устанавливаются из программы после подтверждения. Проверьте переход между двумя подписанными версиями на копии данных Windows/WebView2, включая отказ от установки, ошибочную подпись и отсутствие интернета.

Обычная команда `build:windows` остаётся доступной без ключей и не требует создания подписанного обновления. Rust отслеживает изменение открытого ключа при пересборке. Обновление не переводит Electron в Tauri и не изменяет его установленную версию.

## Проверки текущих изменений

Локально прошли 20 браузерных сценариев Chromium и четыре набора Node (подготовка Tauri, обновления, хранилище Electron, аналитика). Новый сценарий использует синтетический XLSX: автоимпорт отклоняет замечания, ручной предпросмотр открывает тот же файл, отмена не сохраняет, изменённый источник блокируется, подтверждённое сохранение сохраняет замечания и метки источника, исправленный файл впоследствии обновляется автоматически без дублей. Тесты обновления используют имитацию Tauri API: отмена не скачивает, подтверждение запускает установку, ошибки и отсутствие ключа обрабатываются, при активном импорте установка не начинается. Это не проверка реального установщика или криптографической подписи.

Rust и Windows EXE локально не собирались: в этом окружении нет Rust/Windows. Реальный переход между подписанными версиями пока не проверен; ключи и выпуски не созданы. GitHub Actions не запускались. Формат SQLite и JSON не менялся.

## Подписанный выпуск через GitHub Actions

По поручению владельца использование Actions для подписанного Windows-выпуска разрешено. Процесс `Tauri signed Windows release` находится в `.github/workflows/tauri-signed-release.yml`. Он запускается при изменениях в выделенной ветке `build/tauri-signed-20261116`; также доступен ручной повтор через Re-run all jobs. После объединения workflow с основной веткой доступен обычный workflow_dispatch. Обычные изменения HTML не запускают этот процесс.

Владелец добавляет три **repository secrets** в Settings → Secrets and variables → Actions:

- `TAURI_SIGNING_PRIVATE_KEY` — полное содержимое закрытого файла `analiz-updater.key` (не путь на своём компьютере).
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль закрытого ключа.
- `ANALIZ_UPDATER_PUBLIC_KEY` — полное содержимое `analiz-updater.key.pub`.

Ключи создаются один раз и хранятся вне исходников. Сохраните отдельную резервную копию: смена ключа нарушит обновления уже установленных подписанных версий. Не загружайте архив с ключами в Releases, Issues, репозиторий, артефакты Actions или переписку. Секреты добавляются только через настройки GitHub; подключение ассистента не имеет права ими управлять.

Без секретов выполняется только короткая проверка на Ubuntu; Windows-сборка пропускается, а Step Summary перечисляет недостающие **имена**, без значений. Зелёный статус такой проверки не означает готовность установщика. После добавления секретов откройте исходный запуск и нажмите **Re-run all jobs**.

При наличии секретов процесс проверяет Node-наборы и SQLite, собирает подписанный Tauri, сохраняет только установщик, подпись и публичный манифест в артефакт `Tauri-signed-Windows`. Затем создаётся prerelease `tauri-v0.1.1` и обновляется отдельный prerelease `tauri-updates`. Ни один выпуск не становится latest, чтобы не менять постоянную ссылку Electron. Закрытый ключ и пароль в артефакты не входят. Уже опубликованный установщик версии не перезаписывается. Если повторная сборка даёт другую подпись для существующей версии, публикация прекращается: нужно проверить выпуск и увеличить версию. Если загрузка канала не удалась, готовый версионный установщик остаётся доступен; это не считается полностью завершённой публикацией.

Локально проверены YAML, пять Node-наборов, создание зашифрованного ключа и подпись тестового файла официальным Tauri CLI 2.12.5. Публикация тестируется с имитацией GitHub CLI: порядок операций, сбой загрузки и запрет замены существующей подписи. Эти тесты не публикуют релизы и не заменяют реальную сборку Windows.

В конфигурации WebView прежний `csp: null` заменён явной политикой: локальные скрипты, стили, изображения и IPC Tauri; выполнение eval не разрешено. При сборке Tauri добавляет хеши встроенных скриптов HTML. Совместимость импорта и графиков с политикой проверяется в Chromium с вычисленными хешами; проверка фактической упаковки политики в WebView2 остаётся частью Windows-сборки и ручного запуска.

В первом Windows-запуске обнаружена несовместимость тестового поиска функции с CRLF. Тест теперь проверяет оба формата перевода строк (LF/CRLF); сам распознаватель дат и производственный импорт не менялись.
