# Анализ работ — Tauri для Windows

Основная платформа — Windows x64, Tauri 2 и системный WebView2. Личные данные хранятся в SQLite в папке «Документы/Анализ работ». При подключении к общей папке компьютеры обмениваются проверенными снимками отчётов. Корневой [`index.html`](../index.html) используется при подготовке интерфейса Tauri.

## Общая база сотрудников

1. Создайте на файловом сервере одну пустую папку для отчётов, например `\\SERVER\Отчёты`. Предоставьте сотрудникам, которые будут вносить отчёты, право изменения файлов в этой папке.
2. На каждом компьютере откройте «Управление → Базы данных → Подключить общую папку» и выберите тот же сетевой путь. Программа запомнит его. Первое подключение к пустой папке начинает работу без отчётов. Личная SQLite остаётся на компьютере.
3. На одном компьютере проверьте и сохраните первый Excel обычным способом. Откройте «Отчёты» на другом компьютере. После автоматической проверки связи там появится тот же отчёт. Повторная загрузка Excel не требуется. Роли сотрудников в приложении не настраиваются. Право записи выдаёт администратор сетевой папки. Выбор книги и предпросмотр сами по себе ничего не публикуют. Автоимпорт из папки Excel отдельно включается на текущий сеанс и обрабатывает новые отчёты с сохранённым правилом без конфликтов и замечаний.

В «Отчётах» над импортом показана выбранная база. Кнопка «Управление базами» открывает этот же экран. Через «Перейти в личную базу» можно вернуться к своим данным. Переключение останавливает автоимпорт в текущем сеансе, отчёты обеих баз сохраняются. Если отправка изменений не подтверждена, сначала повторите отправку или явно отмените неподтверждённые изменения.

На вкладке «Базы данных» можно сохранить проверенную копию выбранной базы в новый файл SQLite и открыть папку с ним. Для восстановления выберите личную базу и проверьте файл копии. Приложение покажет число отчётов сейчас и после замены. Подтверждённое восстановление выполнится при следующем запуске. До перезапуска его можно отменить.

На сетевом диске приложение хранит снимки базы. Для каждого изменения нужно место под полный снимок. При обрыве связи во время записи откройте «Управление → Базы данных» и проверьте состояние публикации. Если программа предлагает «Повторить отправку», используйте эту кнопку. При конфликте сверьте уже сохранённые отчёты перед новым импортом.

Если приложение сообщает, что в общей папке пропало подтверждённое поколение, восстановите исходные `analiz-generation-*.snapshot` из копии сервера и нажмите «Повторить подключение». При обычном сбросе через «Управление → Базы данных → Сбросить общую базу» приложение публикует новое пустое поколение и оставляет прежние снимки в папке. После синхронизации коллеги увидят пустую общую базу. Для просмотра прежних отчётов можно подключить отдельную папку с копиями прежних снимков.

Если все снимки уже намеренно вынесены из общей папки и нужно начать с пустой базы по тому же пути, подтвердите сброс в этой папке. Новый снимок будет связан с последним подтверждённым поколением. Компьютеры, подтвердившие то же поколение, подключатся после синхронизации. Для компьютеров с более ранним подтверждённым поколением требуется вернуть их исходные снимки. Перед таким сбросом обновите приложение у всех участников. Личные отчёты, локальные правила Excel и исходные файлы сохраняются.

## Выборочный перенос личных отчётов в общую базу

После подключения общей папки в «Управление → Базы данных» появится раздел «Перенос отчётов из личной базы». Программа показывает по 25 личных отчётов с пометкой о пересечении периодов; пользователь выбирает новые отчёты и подтверждает перенос. Записи из личной базы не удаляются. Существующие периоды общей базы **не перезаписываются**, а старый предпросмотр нельзя применить после изменения ревизии.

Перед добавлением формируется проверенная SQLite-копия общей базы в частном каталоге `transfer-backups` на исходном компьютере. Записи сохраняются транзакционно и публикуются через штатный механизм снимков сетевой папки. Если публикация прервалась, не нажимайте перенос повторно: сперва проверьте состояние публикации в «Базы данных» и повторите синхронизацию.

Переносятся обычные и широкие отчёты выбранных периодов. Связанные диагностические записи можно передавать несколькими пакетами: сначала исходный отчёт, затем зависимые, причём его содержимое повторно сверяется. За одну операцию выбирается не более 25 отчётов; выбор сохраняется при переходах между страницами списка. Повторно переносить идентичные записи не нужно — они отмечаются «Уже есть». Отчёты других видов (например, недельные и дневные) могут существовать в одной базе даже при пересечении календарных дат; конфликты проверяются в пределах типа отчёта.

Если общая база ещё пуста и у неё нет пользовательских настроек, при первом переносе из личной базы автоматически устанавливаются названия четырёх подразделений — иначе отчёты могли бы не отображаться в аналитике. В уже используемой общей базе подразделения **не изменяются**: отчёт с неизвестным подразделением нельзя перенести, пока названия не согласованы. **Дополнительные виды отчётов**, группы, справочник и прочие личные настройки не переносятся. Локальные пути к исходным Excel исключаются из перенесённых записей.

## Импорт Excel

Используйте «Импорт Excel» или настройте папку источников в «Управление → Отчёты». Приложение поддерживает обычные отчётные периоды и широкие дневные таблицы. Для широких книг можно выбрать несколько листов, а для последовательных пар без дат указать год и квартал или год целиком. Проверьте найденные периоды и замечания перед сохранением. [Форматы и ограничения Excel](../docs/DAILY_WIDE_REPORTS.md).

## Сборка Windows

Средства ниже нужны разработчику для сборки, а не пользователю для установки готового EXE. GitHub Actions не обязателен: [проверенный способ кросс-сборки из Linux](../docs/TAURI_WITHOUT_ACTIONS.md) описан отдельно.

Для сборки нужны Windows 10/11 x64, WebView2, Node.js 24, Rust и Microsoft C++ Build Tools. Выполните из корня репозитория:

```powershell
npm install --prefix tauri
node --test tauri/tests/*.test.cjs tests/*.cjs
npm --prefix tauri run prepare:frontend
npm --prefix tauri run icons
cargo test --manifest-path tauri/src-tauri/Cargo.toml
npm --prefix tauri run build:windows
```

Готовый NSIS-установщик появляется в `tauri/src-tauri/target/release/bundle/nsis/`. Команда `build:windows` создаёт локальную сборку без настройки публикации обновлений. Тесты папочного импорта находятся в `tests/test_folder_importer.cjs`; устаревшие Electron-тесты исключены.

### Подписанные обновления

- `ANALIZ_UPDATER_PUBLIC_KEY` — открытый ключ проверки; `TAURI_SIGNING_PRIVATE_KEY` — закрытый ключ (GitHub Secret); `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль ключа, если нужен. **Никогда не загружать закрытый ключ в репозиторий.**
- `npm --prefix tauri run build:signed:windows` собирает установщик и `.sig`, но **не публикует** их автоматически.
- Workflow [`Tauri signed Windows release`](../.github/workflows/tauri-signed-release.yml) сначала проверяет ключи без публикации; новый релиз требует отдельного ручного `workflow_dispatch`, новой версии, заметок и успешного Windows CI точного SHA. [Инструкция](../docs/SIGNED_UPDATES.md).
- Используйте отдельный уникальный тег для каждого выпуска. [Порядок выпуска](../docs/RELEASE_POLICY.md).
